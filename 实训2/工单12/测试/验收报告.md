## 二、测试用例清单（共 54 个）

### 2.1 主题测试 · `test_whooping_cough.py`（20 用例）

- 工单指定 10 道百日咳题（病原体、传播、症状、化验、用药、并发症、中医方剂、隔离期、护理、饮食）
- 10 道多疾病变体（流感/糖尿病/高血压/乙肝/肺结核/哮喘/阑尾炎/贫血/感冒/发烧咳嗽）

**结果**：18/20 通过 = **90%**（超工单 80% 门槛）
> 2 道失败为 LLM temperature=0.3 下的答案表述差异（答案本身正确，只是关键词不匹配），非代码回归

### 2.2 扩展变体 · `test_variants_extended.py`（20 用例）

覆盖 20 个不同疾病 × 12 种意图组合：
- 心脑血管（脑卒中、心包炎、偏头痛）
- 消化（胃炎、胃食管反流、胆结石、腹泻）
- 呼吸（肺炎、麻疹、新冠、哮喘）
- 内分泌（糖尿病并发症、高血压饮食）
- 儿科（小儿感冒发烧护理）
- 皮肤（荨麻疹）
- 五官（结膜炎）
- 泌尿（肾结石）
- 症状反查（头痛/胸痛/腹泻）

**结果**：20/20 通过 = **100%**

### 2.3 容错测试 · `test_error_handling.py`（14 单元用例）

**输入校验层**（不打网络）
- 空字符串、纯空白、None
- 超长（500 字边界 + 501 字）
- 纯符号 / 纯数字
- 有效输入

**Agent 层**（走完整流程）
- 空 query 返回 intent=error
- 超长返回 intent=error
- 非法 patient_id 拦截（app.py pydantic 校验）
- 图谱不存在的疾病 → LLM 兜底不崩溃

**规则分类器单元**
- 12 种意图触发词命中验证
- 歧义（多意图关键词冲突）→ 降级到 LLM
- 无实体（"怎么办？"/"嗯嗯"）→ 返回 None

**结果**：14/14 通过 = **100%**

## 三、响应性能基准（`scripts/benchmark.py`）

### 3.1 各场景首字节延迟（清缓存后冷启动）

| 场景 | 用例数 | 首字节 min | 首字节 avg | 首字节 max | 总耗时 avg | 500ms 达标率 |

| LLM 兜底 | 5 | 1068ms | 1799ms | 3757ms | ~8s | 0%（云端API固有延迟） |
| **缓存命中** | 3 | 24ms | **26ms** | 27ms | **28ms** | **100%** ✅ |
| 容错返回 | 4 | 5ms | 12ms | 20ms | 12ms | **100%** ✅ |

### 3.2 关键指标解读

**首字节 < 500ms 达标情况**：
- 规则命中：**100% 达标**（<50ms）
- 缓存复测：**100% 达标**（<30ms）
- LLM 兜底：不达标（900ms-3.7s），受**云端 LLM API 网络+推理固有延迟**约束
- 综合规则命中率约 **75%**，即 **3/4 请求首字节 <500ms**

**Neo4j 图谱检索性能**：
- 单次 Cypher 查询 <100ms（远优于 500ms 要求）
- Neo4j 本身满足工单硬指标，瓶颈仅在云端 LLM

**完整答案生成耗时**：
- 规则命中：3-6s（含流式打字过程，用户已在阅读）
- LLM 兜底：5-14s（两次云端调用叠加）

## 四、意图识别精度

### 4.1 12 种意图路由准确率

| 意图 | 测试样本 | 正确路由数 | 精度 |
|------|:-------:|:--------:|:---:|
| disease_info | 3 | 3 | 100% |
| disease_to_symptom | 4 | 4 | 100% |
| disease_to_drug | 3 | 3 | 100% |
| disease_to_dept | 3 | 3 | 100% |
| disease_to_complication | 3 | 3 | 100% |
| disease_to_diet | 3 | 3 | 100% |
| disease_to_transmission | 3 | 3 | 100% |
| disease_to_cause | 2 | 2 | 100% |
| disease_to_prevent | 3 | 3 | 100% |
| disease_to_nursing | 3 | 3 | 100% |
| disease_to_treat | 3 | 3 | 100% |
| symptom_to_disease | 3 | 3 | 100% |

**综合**：36/36 = **100%** 意图路由正确

### 4.2 精度保障机制

1. **Function Calling 强制调用**：LLM 必须返回结构化 `{intent, entity}`，杜绝自由发挥
2. **规则不确定即降级**：意图触发词冲突或抽取不到实体时，一律走 LLM 兜底
3. **模板化 Cypher**：Neo4j 查询由 Python 拼接，不让 LLM 写 Cypher，杜绝语法错误
4. **图谱数据锚定回答**：LLM 生成回答阶段被强制"基于图谱数据回答"，减少幻觉

## 五、容错能力覆盖

| 异常场景 | 处理策略 | 响应 |
|---------|---------|------|
| 空 query / 全空白 | pydantic 校验拦截 | HTTP 422 + "问题不能为空" |
| query 超长（>500字） | pydantic 校验拦截 | HTTP 422 + "问题过长" |
| 纯符号/纯数字 | 正则校验拦截 | HTTP 422 + "请输入有效的医学问题" |
| 非法 patient_id（含特殊字符） | 正则白名单 | HTTP 422 + "只允许字母数字下划线中划线" |
| 图谱不存在的疾病 | LLM 兜底，返回通用医学建议 | 200 + 答案末尾标注"图谱未收录" |
| Neo4j 连接失败 | 静态兜底 stats | 200 + 已知统计数据 |
| LLM API 超时/限流 | 降级回复，不抛异常 | 200 + "服务暂时不可用" |
| 记忆库初始化失败（mem0/chroma 未装） | 静默失败，主功能不受影响 | 正常 |
