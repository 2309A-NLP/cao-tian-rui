## 二、各阶段实现详情

### Phase 1：数据库层

基于原 `E:\16---实训2\工单11` 的 SQLite 版本，迁移至 MySQL 8.0。

**主要改动：**
- 占位符：SQLite `?` → MySQL `%s`
- 连接方式：`sqlite3.connect()` → `pymysql.connect()` + DBUtils.PooledDB
- 类型：`TEXT` → `VARCHAR`，`REAL` → `DECIMAL`
- 事务管理：`with db_transaction() as conn` 上下文管理器封装 commit/rollback

**种子数据覆盖：**
- 3个科室（儿科、牙科、内科）
- 6名医生
- 14天排班（每日2-3个时段）
- 3个患者（用户本人 + 大宝 + 二宝）

---

### Phase 2：工具函数层（tools.py）

按工单需求实现 6 个工具函数，每个函数均包含：
- 入参验证（科室白名单、日期范围检查）
- 结构化日志（`logger.log_tool_call`，含耗时）
- 异常捕获 → 返回 `{"ok": False, "error": "..."}`

**挂号并发安全实现（book_appointment）：**
```python
# 行锁读最新号源
SELECT ... FROM schedule WHERE sch_id = %s FOR UPDATE

# 原子更新，rowcount==0 表示被别人抢先
UPDATE schedule SET sch_available = sch_available - 1
WHERE sch_id = %s AND sch_available > 0

if cur.rowcount == 0:
    return {"ok": False, "error": "号源已被抢完"}
```

### Phase 3：Agent 层（agent.py）

核心是 `_run_fc_loop` 函数，实现标准 Function Calling 循环：

```
while 轮次 < MAX_ROUNDS:
    调用 LLM（传入 messages + tools 定义）
    if LLM 返回 tool_calls:
        for each tool_call:
            执行对应的 Python 函数
            序列化结果（含 _DateEncoder 处理 date 对象）
            追加 {"role": "tool", "content": 结果JSON} 到 messages
    elif LLM 返回 content:
        return content  # 最终回复
```

**book-guard 逻辑**：当 LLM 查到号源但没调 book_appointment 时，扫描 tool result 消息，若恰好只有 1 条号源则自动代为预约，避免对话卡死。

### Phase 4：LLM 客户端（llm_client.py）

初版双模型（硅基流动 Qwen2.5-72B + DeepSeek-V3备用）。

**2026-07-07 升级为三级 fallback 链：**

```python
# _MODEL_CHAIN = [(client, model_id, label), ...]
_MODEL_CHAIN = [
    (_bailian_client,     "qwen3.7-plus",               "百炼/qwen3.7-plus"),
    (_siliconflow_client, "Qwen/Qwen2.5-32B-Instruct",  "硅基/32B"),
    (_siliconflow_client, "Qwen/Qwen2.5-14B-Instruct",  "硅基/14B"),
]
```

两个独立 OpenAI 客户端：百炼（`dashscope.aliyuncs.com`）和硅基流动。  
`_call_llm` 接受 `client` 参数，`call_llm_with_fallback` 遍历链，三级均失败时向上抛出交 agent 做规则兜底。  
Qwen3 系列传 `extra_body={"enable_thinking": False}` 关闭 CoT 模式，避免不必要延迟。

### Phase 5：FastAPI 接口层（app.py）

**端点分工：**

| 端点 | 用途 | 是否过 LLM |
|---|---|---|
| GET /health | 健康检查 | 否 |
| POST /chat | Agent 对话 | 是 |
| GET /slots | 号源表格数据 | 否 |
| GET /appointments/{id} | 我的预约+统计 | 否 |
| GET /schedule | 医生排班 | 否 |

REST 端点直查 DB 的设计理由：前端筛选表格需要实时刷新，不应等待 LLM，响应时间目标 <500ms。

---

### Phase 6：前端门户（index.html）

原 prototype.html 是静态演示页，此阶段重写为真实联网版本。

**重写要点：**
1. 所有数据从 API 加载，不再硬编码
2. `_slotRegistry` 全局注册表，避免 onclick 属性中 JSON 双重序列化
3. POST /chat 对话后自动刷新 4 个视图（统计/预约/号源/排班）
4. 统一 `CONFIG` 对象管理 API 地址和鉴权 Key
5. 6 个模块通过 `switchModule(mod)` 切换，默认激活挂号管理

### Phase 7：调试修复

详见《问题与解决方法.md》，共解决 8 个问题，其中核心 2 个：

## 四、关键技术决策记录

| 决策 | 选择 | 放弃 | 理由 |
|---|---|---|---|
| LLM 调用模式 | Function Calling | prompt engineering | FC 强制结构化，杜绝幻觉 |
| DB 连接 | DBUtils.PooledDB | 每次新建连接 | 连接复用，支持并发 50+ |
| 纯查询接口 | REST 直查 DB | 全走 Agent | 查询不需要 LLM，省时省钱 |
| 前端框架 | 纯 HTML+JS | React/Vue | 零构建工具，即开即用 |
| 后端框架 | FastAPI | Flask/Django | 异步、自带文档、Pydantic 验证 |
