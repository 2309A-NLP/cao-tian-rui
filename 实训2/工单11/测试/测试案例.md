# 工单11 挂号管理 - 测试案例文档

> 对应工单要求：6个主案例 + 30+变体场景  
> 用户环境：user_id=1（张三，家属：大宝/二宝），user_id=2（李四）  
> 测试日期范围：2026-07-05 ~ 2026-07-19

---

## 一、6个主测试案例

### Case 1：为家人挂专家号
**输入**: `帮我大宝挂一个今天下午2点儿科专家的号`  
**预期流程**:  
1. Agent 识别就诊人=大宝 → 调 `get_family_member(user_id=1, alias="大宝")` → patient_id=2  
2. 查号源 → `query_schedule(dept="儿科", title="专家", time_pref="14:00", ...)`  
3. 有号源 → 调 `book_appointment(user_id=1, patient_id=2, sch_id=xxx)`  
4. 返回成功确认，含就诊时间和挂号编号  

**预期回复关键词**: 大宝、儿科、专家、成功、挂号编号  
**断言**: `reg_id` 为正整数，MySQL register 表新增一条记录，对应 schedule.sch_available -= 1

---

### Case 2：按科室查询最近号源
**输入**: `牙科最近的号哪天的？`  
**预期流程**:  
1. 意图=查询，科室=牙科  
2. 调 `query_schedule(dept="牙科", date_start=今天, date_end=今天+7天)`  
3. 按日期排序展示号源列表  

**预期回复关键词**: 牙科、日期列表、医生姓名、剩余号源  
**断言**: 返回结果按 sch_date 升序排列

---

### Case 3：基于历史记录再次预约同一医生
**输入**: `我之前挂过眼科的一个专家，帮我再约那个专家的号`  
**预期流程**:  
1. 意图=挂号，含"之前/上次"  
2. 调 `get_user_history(user_id=1, dept="眼科")` 找历史医生  
3. 调 `query_schedule(doctor_name=<历史医生名>, dept="眼科", ...)`  
4. 调 `book_appointment(...)`  

**预期回复关键词**: 找到历史记录、医生姓名、预约成功  
**断言**: history 不为空时必须完成预约，不能只返回号源列表

---

### Case 4：带时间和家属的号源查询
**输入**: `我明天上午9点想带二宝看皮肤科，还有号吗？`  
**预期流程**:  
1. 就诊人=二宝 → patient_id=3  
2. 时间=明天上午 → date=tomorrow, time_pref="09:00"  
3. `query_schedule(dept="皮肤科", date_start=tomorrow, date_end=tomorrow, time_pref="09:00")`  
4. 返回号源情况（有/无）  

**预期回复关键词**: 明天、皮肤科、上午  
**断言**: 只查询不预约（用户只说"还有号吗"而非"帮我约"）

---

### Case 5：取消历史挂号
**输入**: `取消我上周三挂的消化内科普通号`  
**预期流程**:  
1. 意图=取消，科室=消化内科，类型=普通  
2. 解析时间"上周三" → 申请时间（`reg_Time`），非就诊日（Rule 11：date 参数禁止填写）  
3. 先调 `get_user_history(user_id=1, dept="消化内科")` 查出历史记录，找到 `reg_time≈上周三` 的记录，取得 `reg_id`  
4. 调 `cancel_appointment(user_id=1, reg_id=<reg_id>)` 精确取消  
5. 找到记录 → 状态置0 → 号源+1  

**预期回复关键词**: 取消成功、挂号编号  
**断言**: register.reg_Status=0，schedule.sch_available += 1  
**⚠️ 注意**: Agent 不得用 `date` 参数传"上周三"直接取消；必须先 `get_user_history` 查 `reg_id`，再用 `reg_id` 取消（Rule 11）

---

### Case 6：按医生姓名查排班
**输入**: `帮我查下张建国医生下周的坐诊时间`  
**预期流程**:  
1. 意图=排班查询，doctor_name=张建国  
2. 调 `get_doctor_schedule(doctor_name="张建国", date_start=下周一, date_end=下周日)`  
3. 按日期展示坐诊时间（含已满号源）  

**预期回复关键词**: 张建国、下周、时间表格  
**断言**: 返回包含 sch_date/sch_time_slot/sch_type/available 字段

## 二、变体场景（30+）

### 2.1 时间表达变体（Case 1/2/4/5 的时间槽变体）

| # | 输入 | 预期解析 |
|---|------|----------|
| V1 | 今天上午 | today 09:00-11:00 |
| V2 | 今天下午 | today 14:00-17:00 |
| V3 | 今天晚上 | today 19:00-21:00 |
| V4 | 明天早上九点 | tomorrow 09:00-11:00 |
| V5 | 后天下午 | day_after_tomorrow 14:00-17:00 |
| V6 | 这周五上午 | 本周五 09:00-11:00 |
| V7 | 下周一 | next_monday |
| V8 | 下下周（超出14天） | 提示超出可挂号范围 |
| V9 | 上周三 | 过去日期，取消/查询历史用 |
| V10 | 最近最早的号 | date_start=today, date_end=today+7 |

### 2.2 就诊人表达变体

| # | 输入 | 预期解析 |
|---|------|----------|
| V11 | 帮我挂... | alias="我" → patient_id=1 |
| V12 | 我自己 | alias="我" → patient_id=1 |
| V13 | 大宝 | alias="大宝" → patient_id=2 |
| V14 | 二宝 | alias="二宝" → patient_id=3 |
| V15 | 三宝（不存在） | 提示未找到，引导添加家属 |
| V16 | 帮我老婆挂 | 未找到别名"老婆"，提示确认 |

### 2.3 号源类型变体

| # | 输入 | 预期解析 |
|---|------|----------|
| V17 | 专家号 | sch_type="专家" |
| V18 | 普通号 | sch_type="普通" |
| V19 | 主任医师的号 | 模糊映射到"专家" |
| V20 | 不指定类型 | 返回专家+普通全部 |

### 2.4 号源不足场景

| # | 场景 | 预期行为 |
|---|------|----------|
| V21 | 该时段号源=0 | 告知已满，推荐同科室其他时间/医生 |
| V22 | 所有号源均已满 | 告知全满，推荐下一工作日 |
| V23 | 并发抢最后一个号 | InnoDB FOR UPDATE 行锁保证只有一人成功，另一人返回"已被抢完" |

### 2.5 异常输入（容错）

| # | 输入 | 预期行为 |
|---|------|----------|
| V24 | 无效用户ID（user_id=999） | 返回"用户不存在" |
| V25 | 错误时间格式（"下午三百点"） | dateparser 解析失败 → 询问确认 |
| V26 | 不存在的科室（"火星科"） | 模糊匹配失败 → 提示不存在，列出可用科室 |
| V27 | 拼写错误科室（"口科"）| 模糊匹配 → 建议"口腔科"（牙科） |
| V28 | 重复挂同一号源 | 返回"已挂过，请勿重复" |
| V29 | 挂过去日期（昨天） | 返回"不可挂过去日期" |
| V30 | 取消已取消的记录 | 返回"该记录已取消" |
| V31 | 取消过期挂号（就诊日已过） | 返回"不可取消已过期挂号" |

### 2.6 复杂意图变体

| # | 输入 | 预期行为 |
|---|------|----------|
| V32 | 帮我挂今天下午儿科和2:30眼科（时间冲突） | 检测同时段冲突，提示两者时段重叠 |
| V33 | 我之前挂的那个专家（无具体科室） | 查全部历史 → 列出历史 → 引导用户确认 |
| V34 | 凌晨一点有号吗 | 提示非门诊时间段，推荐上午/下午/晚上 |
| V35 | 帮我查所有科室今天的号 | 调用全科室查询（GET /slots 无科室过滤） |

## 三、REST 接口测试

### GET /slots
```bash
# 基础查询
curl "http://localhost:8011/slots?dept=儿科&date_start=2026-07-07&date_end=2026-07-08"

# 无科室（全部）
curl "http://localhost:8011/slots?date_start=2026-07-07&date_end=2026-07-07"

# 指定类型
curl "http://localhost:8011/slots?dept=眼科&slot_type=专家"
```

### GET /appointments/{user_id}
```bash
# 所有记录+统计
curl "http://localhost:8011/appointments/1"

# 只看待就诊（就诊日未到）
curl "http://localhost:8011/appointments/1?bucket=upcoming"

# 只看历史预约（已过期或已取消）
curl "http://localhost:8011/appointments/1?bucket=history"
```

### GET /schedule
```bash
# 查医生排班
curl "http://localhost:8011/schedule?doctor=张建国"
curl "http://localhost:8011/schedule?doctor=李华&date_start=2026-07-07&date_end=2026-07-14"
```

### POST /chat（Agent 对话）
```bash
curl -X POST http://localhost:8011/chat \
  -H "Content-Type: application/json" \
  -d '{"user_id": 1, "query": "帮我大宝挂一个今天下午2点儿科专家的号"}'
```

## 四、性能基准

| 指标 | 要求 | 实现方案 |
|------|------|----------|
| 响应时间（纯查询） | <500ms | REST 接口直接走 SQL，无 LLM |
| 挂号事务处理 | <1s | MySQL InnoDB 行锁，单条 INSERT |
| Agent 响应（含 LLM） | <3s | 百炼 qwen3.7-plus，enable_thinking=False，2轮 FC |
| 并发 50 用户 | 不崩溃 | DBUtils 连接池 maxconnections=20 |
