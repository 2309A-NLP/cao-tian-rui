## 二、优化详情

### 优化1 — 修复 date 对象 JSON 序列化（严重）

**文件**: `backend/src/agent.py:330`  
**类型**: 正确性 Bug  
**影响**: 所有经 LLM 的挂号/取消对话均失败，退回简易模式

**问题代码**:
```python
content = json.dumps(result, ensure_ascii=False)
```

**原因**: MySQL DictCursor 返回 `datetime.date` 对象，标准 `json.dumps` 无法序列化，抛 `TypeError`，导致整个 FC 循环中断。

**修复代码**:
```python
content = json.dumps(result, ensure_ascii=False, cls=logger._DateEncoder)
```

**效果**: LLM 功能完全恢复，对话正常。

### 优化2 — 修复 DBUtils 连接对象调用方式（严重）

**文件**: `backend/src/agent.py:343`  
**类型**: 正确性 Bug  
**影响**: `_pre_validate` 函数报 `AttributeError`，用户存在性验证失败

**问题代码**:
```python
row = conn.execute("SELECT ua_id FROM user_account WHERE ua_id = ?", (user_id,)).fetchone()
```

**原因**: SQLite 连接对象支持 `.execute()`，但 `DBUtils.PooledDB` 的 `SteadyDBConnection` 不支持，必须先获取游标。占位符也需从 `?` 改为 `%s`。

**修复代码**:
```python
cur = conn.cursor()
cur.execute("SELECT ua_id FROM user_account WHERE ua_id = %s", (user_id,))
row = cur.fetchone()
```

### 优化3 — book-guard 盲选第一条号源（逻辑错误）

**文件**: `backend/src/agent.py:488`  
**类型**: 正确性 Bug（逻辑）  
**影响**: 用户明确说要"下午"，guard 可能选了"上午"的号源

**问题代码**:
```python
# 原实现：只要 schedules 非空就取第一条
if _all_schedules:
    _sch_id = _all_schedules[0].get("sch_id")
```

**原因**: 当查询返回多条号源时（如上午+下午各一条），guard 无条件选第一条，忽略了用户的时间偏好。

**修复代码**:
```python
# 仅当恰好只有1条时自动选，多条时放弃让 LLM 重试
if _all_schedules and len(_all_schedules) == 1:
    _sch_id = _all_schedules[0].get("sch_id")
# else: 不自动选，避免选错时段
```

### 优化5 — 日期上界缺失（安全+数据正确性）

**文件**: `backend/src/tools.py:119` + `backend/src/app.py:102`  
**类型**: 输入验证缺失  
**影响**:
- `query_schedule` 可被传入任意远未来日期（如2099年），导致无效查询
- `GET /slots` 日期参数无格式验证，非法字符串直接传入 SQL

**tools.py 修复**:
```python
# 在 query_schedule 中强制 date_end 上界
max_end = (date.today() + timedelta(days=MAX_FUTURE_DAYS)).isoformat()
if date_end > max_end:
    date_end = max_end
```

**app.py 修复**:
```python
# GET /slots 日期格式验证
for label, val in [("date_start", date_start), ("date_end", date_end)]:
    if val:
        try:
            date.fromisoformat(val)
        except ValueError:
            raise HTTPException(status_code=422, detail=f"{label} 格式无效，需 YYYY-MM-DD")

# 同时加 slot_type 白名单校验
if slot_type and slot_type not in VALID_TITLES:
    raise HTTPException(status_code=422, detail=f"slot_type 无效，可选: {VALID_TITLES}")
```

### 优化6 — CORS 含 "null" 允许任意本地文件跨域（安全）

**文件**: `backend/src/app.py:32`  
**类型**: 安全漏洞  
**影响**: `allow_origins` 含 `"null"` 时，任何通过 `file://` 打开的本地 HTML 文件都可以调用后端所有接口（浏览器对 file:// 的 Origin 头为 null）

**问题配置**:
```python
"http://localhost:5500,...,null"   # null 覆盖了所有本地文件
```

**修复**:
```python
# 仅保留明确的 localhost 开发源，移除 "null"
_origins = [
    "http://localhost:8011", "http://127.0.0.1:8011",
    "http://localhost:8000", "http://127.0.0.1:8000",  # 统一门户入口
    "http://localhost:3000", "http://127.0.0.1:3000",
    # "null" 已移除
]
```

**附加说明**: 前端改用 `python -m http.server 8000` 提供门户服务（Origin: http://localhost:8000），统一端口约定，不再依赖 file:// 访问，因此移除 null 不影响功能。

## 五、2026-07-07 功能迭代优化

### 优化7 — Agent思考过程折叠面板（B方案）

**文件**: `src/agent.py`, `src/app.py`, `00-总界面框架/index.html`  
**类型**: 新功能  

`run_agent()` 返回值从 `str` 改为 `{"reply": str, "trace": list}`，每次工具调用生成一个 trace 步骤（含 step/tool/label/input/output/ok）。`ChatResponse` 新增 `trace` 字段。前端 AI 回复上方渲染"🔍 查看执行过程（N步）"折叠面板，点击展开逐步显示工具调用详情。

---

### 优化8 — "我的预约"分待就诊/历史预约Tab

**文件**: `src/app.py`, `00-总界面框架/index.html`  
**类型**: 功能增强  

`/appointments/{user_id}` 新增 `bucket` 查询参数（`upcoming`/`history`），后端 `_classify()` 函数按就诊日和当前时刻判断分桶。前端拆分为两个子 Tab，"取消"按钮仅在 `bucket=upcoming && reg_status=1` 时显示，防止对已过期记录误操作。

### 优化9 — 种子数据重构

**文件**: `scripts/init_db.py`  
**类型**: 测试数据质量  

- `DOCTOR_PATTERN` 按职称规范：主任/副主任 → `["专家"]`，主治 → `["普通"]`，消除同医生同时段专家+普通并存的逻辑错误
- 5条覆盖全用例的演示挂号记录（含眼科历史、消化内科可取消记录、已取消历史）
- 消化内科演示记录：`reg_Time=上周三`（申请时间）、`sch_date=未来工作日`（就诊日），满足"取消上周三挂的"场景
- 新增 `--reset` CLI 参数，支持一键清空重建

### 优化10 — 取消歧义规则（Rule 11）

**文件**: `src/agent_prompts.py`  
**类型**: LLM行为修正  

System Prompt 新增规则11：用户说"取消我 X 号/上周 X 挂的号"，X 指申请时间而非就诊日期，此时 `date` 参数**禁止填写**，必须先调 `get_user_history` 查出记录，再用 `reg_id` 精确取消。同步更新 `cancel_appointment` 工具的 `date` 参数描述，嵌入歧义警告。

---

### 优化11 — LLM升级至百炼qwen3.7-plus + 三级fallback

**文件**: `src/llm_client.py`, `src/config.py`, `.env`  
**类型**: 性能优化  

从单端点双模型升级为双端点三级链：  
百炼 qwen3.7-plus（主）→ 硅基 Qwen2.5-32B（兜底2）→ 硅基 Qwen2.5-14B（兜底3）→ 规则正则（兜底4）。  
`_call_llm` 新增 `client` 参数支持多端点。Qwen3 系列传 `enable_thinking=False` 关闭 CoT 避免无效延迟。

---

### 优化12 — CORS补全8080端口 + 禁止内部推理暴露

**文件**: `.env`, `src/agent_prompts.py`  
**类型**: Bug修复 + 输出质量  

`.env` 的 `CORS_ORIGINS` 补充 `:8080`，支持前端用 `http.server 8080` 启动时正常跨域。System Prompt 输出格式规则末尾新增：禁止在最终回复中暴露内部推理过程（如"让我确认一下…"），直接给出结论。
