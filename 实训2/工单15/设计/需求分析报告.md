## 一、需求概述

### 1.1 业务背景
在医疗场景中，实时语音能力有多重价值:
1. **患者-医生对话记录**: 门诊时自动记录医患对话，生成摘要
2. **跨语言就医**: 外籍患者或少数民族患者的实时翻译需求
3. **会议/会诊纪要**: 科室会议、病例讨论的智能记录和总结
4. **语音交互入口**: 不方便打字的场景下（如老年人）通过语音与 Agent 交互

本模块通过 **对接阿里云通义听悟** 实现上述能力。

### 1.2 目标用户
- **患者**: 语音交互、对话记录、翻译需求
- **医生**: 门诊记录、会诊纪要
- **家属**: 代问诊时的记录和翻译

```

    |

    |                   |
    |                   +-- 实时输出: 识别文本、翻译文本
    |
    +-- HTTP API --> 通义听悟任务管理
    |                   |
    |                   +-- 创建任务 --> 获取 task_id

    |
    +-- 回调接口 <-- 通义听悟回调推送
                        |
                        +-- 任务完成通知
                        +-- 完整结果数据（摘要、章节、待办等）
```

## 四、技术要点

### 4.1 WebSocket 协议 vs HTTP 协议

| 维度 | WebSocket | HTTP |
|------|-----------|------|
| 连接方式 | 长连接，全双工 | 短连接，请求-响应 |
| 实时性 | 低延迟，实时推送 | 轮询有延迟 |
| 适用场景 | 实时语音识别流 | 结果查询、回调 |
| 本模块应用 | 实时语音流传输 | 轮询/回调获取纪要 |

### 4.2 异步与回调设计

```
实时阶段（WebSocket）:
音频流 --> 通义听悟 --> 实时返回识别/翻译文本

异步阶段（HTTP/Callback）:
录音结束 --> 通义听悟处理中 --> 任务完成
                                |
                    +-----------+-----------+
                    |                       |
                回调 URL                轮询查询
                    |                       |
                推送完整结果            主动获取结果
```

### 4.3 并发模型（asyncio 协程）

本工单**不使用多线程**，采用 asyncio 协程模型：

- 协程1: `_browser_to_xf` 上行（浏览器 PCM → 讯飞）
- 协程2: `_xf_to_browser` 下行（讯飞识别结果 → 浏览器）
- 协程3: 句末翻译（`asyncio.create_task` 后台任务，不阻塞识别流）
- 协程4: 回调触发的健康咨询（`_auto_consult()`，后台）
- 回调/轮询本身走 HTTP，由 FastAPI/uvicorn 事件循环统一调度

选用协程理由：I/O 密集（等讯飞、等 LLM）、连接数可能上千、单线程无锁——多线程反而增加锁风险与上下文切换开销。详见 `docs/技术总结.md` §2。

## 五、非功能需求

### 5.1 性能要求
- 语音识别延迟 < 500ms（字级别）
- 翻译延迟 < 1s
- 纪要生成 < 5s（任务结束后）

### 5.2 质量要求
- 语音识别准确率 >= 95%（医疗术语场景）
- 翻译准确率 >= 90%
- 纪要完整性 >= 85%
