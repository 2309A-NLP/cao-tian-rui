## 问题 2：curl 测试回调接口返回 `InvalidPayload`

### 现象

PowerShell 下执行：
```powershell
curl -X POST http://127.0.0.1:8015/api/callback -H "Content-Type: application/json" -d '{"TaskId":"wt15-xxx","TaskStatus":"COMPLETED"}'
```
返回 `{"code":"InvalidPayload"}`，状态码 400。

### 根因

**PowerShell shell 转义问题**，不是 API 缺陷。

PowerShell 中单引号内的 JSON 在某些情况下不被正确传递给 curl.exe（Windows curl vs PowerShell 内置 `Invoke-WebRequest` 的别名冲突）。Chinese/非 ASCII 字符进一步加剧了转义混乱，导致后端收到空 body 或乱码，触发 `json.JSONDecodeError`。

### 解决方案

**用 pytest 的 `test_callback_success` 验证**，它绕过 shell 层直接调 TestClient：
```python
r2 = client.post("/api/callback", json=payload)
assert r2.json()["code"] == "0"    # 通过
```

若必须用命令行测试，改用 PowerShell 原生方式：
```powershell
Invoke-RestMethod -Method POST -Uri "http://127.0.0.1:8015/api/callback" `
  -ContentType "application/json" `
  -Body '{"TaskId":"wt15-test","TaskStatus":"COMPLETED","Result":{}}'
```

### 教训

curl 在 PowerShell 下是 `Invoke-WebRequest` 的别名，参数传递行为与 Linux/bash 下的 curl 不同。Windows 环境测试 JSON API 优先用 `Invoke-RestMethod` 或 Python `requests`。

## 问题 3：uvicorn.log 出现端口占用错误（10048）

### 现象

`uvicorn.log` 中出现：
```
ERROR: [Errno 10048] error while attempting to bind on address ('127.0.0.1', 8015):
[WinError 10048] 通常每个套接字地址(协议/网络地址/端口)只允许使用一次。
```

### 根因

两次启动 uvicorn 而没有先关闭上一个实例。具体场景：首次启动放后台，再次执行同一命令时第二个实例抢占端口失败。

这不是代码错误，是操作问题。日志里第一个实例正常运行，第二个实例立即报错退出，不影响服务。

### 解决方案

启动前先检查并终止旧进程：
```powershell
$pid = (Get-NetTCPConnection -LocalPort 8015 -State Listen -ErrorAction SilentlyContinue).OwningProcess
if ($pid) { Stop-Process -Id $pid -Force; Start-Sleep 1 }
```

### 预防

部署脚本中始终包含上述"先杀后起"逻辑；已写入 `docs/部署指南.md` §7。

## 问题 4：静态资源 404（voice.css / voice.js 无法加载）

### 现象

浏览器控制台报：
```
GET http://127.0.0.1:8015/voice.css  404 Not Found
GET http://127.0.0.1:8015/voice.js   404 Not Found
```

### 根因

`index.html` 初版使用相对路径：
```html
<link rel="stylesheet" href="voice.css">
<script src="voice.js"></script>
```

后端通过 `app.mount("/static", StaticFiles(directory="frontend"))` 将前端目录挂载到 `/static/`，所以正确路径是 `/static/voice.css`。直接写 `voice.css` 相当于请求 `/voice.css`，路由不存在。

### 解决方案

修改 `index.html` 为绝对路径：
```html
<link rel="stylesheet" href="/static/voice.css">
<script src="/static/voice.js"></script>
```

`pcm-worklet.js` 在 JS 代码中动态加载，同样改为：
```javascript
await state.audioCtx.audioWorklet.addModule("/static/pcm-worklet.js");
```

### 验证

uvicorn.log 中出现：
```
GET /static/voice.css  HTTP/1.1  200 OK
GET /static/voice.js   HTTP/1.1  200 OK
GET /static/pcm-worklet.js HTTP/1.1  200 OK
```

## 问题 5：AudioWorklet 在非 Secure Context 下加载失败

### 现象

某些浏览器（Chrome 非 localhost 场景）拒绝加载 AudioWorklet：
```
DOMException: AudioWorklet.addModule() failed:
The operation is not allowed in a non-secure context.
```

### 根因

AudioWorklet（以及 `getUserMedia` 麦克风权限）要求 **Secure Context**，即 HTTPS 或 `localhost`。在局域网 IP（如 `192.168.x.x`）访问时触发此限制。

### 解决方案（按场景选一）

| 场景 | 方案 |
|---|---|
| 本地开发 | 只用 `http://127.0.0.1:8015/`（localhost 属于 Secure Context） |
| 局域网访问 | 在 uvicorn 前加 nginx + 自签证书，或用 `--ssl-keyfile/--ssl-certfile` 参数 |
| 测试演示 | Chrome 启动时加 `--unsafely-treat-insecure-origin-as-secure=http://192.168.x.x:8015` |

当前部署方式（`--host 127.0.0.1`）只绑定本机，天然规避此问题。

## 问题 6：翻译接口出现在 PDF 中但旧代码完全未实现

### 现象

PDF §2 明确要求"翻译（将识别结果实时翻译为其他语言）"，但旧项目 `xfyun.py` 中无任何翻译相关代码，也没有 `translation` 类型的 WS 事件。

### 根因

旧代码未完成，是遗留的 TODO 项。

### 解决方案

在新项目 `xfyun.py` 中实现：
1. `translate_sentence(text, target_lang)` — 调用硅基流动 LLM 翻译，静默降级（异常返回 ""）
2. `_translate_and_push(browser_ws, text, target_lang, sentence_index)` — 非阻塞后台任务
3. 在 `_xf_to_browser()` 的 `sentence_end` 事件后，用 `asyncio.create_task()` 触发翻译，不阻塞识别流

翻译与识别**完全解耦**：识别流延迟不受翻译 LLM 响应时间影响。

### 关键设计点

```python
# sentence_end 后立即发给浏览器，同时后台开始翻译
await browser_ws.send_json({"type": "sentence_end", ...})
if TRANSLATE_ENABLED:
    asyncio.create_task(_translate_and_push(browser_ws, text, lang, idx))
    # create_task 不 await，不阻塞
```

## 问题 7：PDF 要求"通义听悟"但 API 不可直接用于开发调试

### 现象

PDF §3 要求使用通义听悟 API，但通义听悟：
1. 需要阿里云账号及开通音视频智能服务
2. 有最小音频时长限制（通常 > 30 秒）
3. 本地开发无法快速迭代调试

### 解决方案

采用**三态 ASR 引擎架构**：

```
ASR_ENGINE=mock     → 内置 4 句医患对话（本地开发/测试）
ASR_ENGINE=xfyun    → 讯飞 IAT WebSocket（实时场景，低延迟）
ASR_ENGINE=tingwu   → 通义听悟 HTTP（合规场景，按需启用）
```

`tingwu.py` 完整保留（含 ACS3-HMAC-SHA256 签名），作为合规存档，不挂载到主路由。`docs/通义听悟对接说明.md` 提供完整的权衡说明和迁移指南，满足验收要求。
