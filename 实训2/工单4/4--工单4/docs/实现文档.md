## 2. 各模块实现说明

### 2.1 config.py

**职责**：统一加载 `.env` 配置，暴露所有配置常量。

**关键设计**：
```python
_BASE_DIR = Path(__file__).resolve().parent.parent  # 项目根目录

def _resolve_path(env_key, default):
    """相对路径以项目根目录为基准转为绝对路径"""
    raw = os.getenv(env_key)
    p = Path(raw)
    return p if p.is_absolute() else (_BASE_DIR / p).resolve()
```

> **原因**：直接用相对路径时，从不同目录运行脚本会导致路径解析出错（如 `FileNotFoundError`）。固定以项目根目录为基准可完全避免此问题。

### 2.3 nl2sql.py

**职责**：调用 LLM API，将自然语言问题转换为 SQLite SQL。

**关键参数**：

```python
    messages=[...]
```

**提示词规则要点**（共18条）：

- 日期格式：YYYYMMDD 文本，不用 DATE() 函数
- 列名规范：双引号包裹，含括号列如 `"收盘价(元)"`、`"昨收盘(元)"`
- 涨跌幅公式：`("收盘价(元)" - "昨收盘(元)") / "昨收盘(元)" * 100`，禁止用前一日数据自连接
- 基金代码：禁止硬编码，必须 JOIN `基金基本信息` 通过名称查代码
- 行业过滤：`= '中信行业分类'` 精确匹配（LIKE 前置通配符会导致索引失效）
- 可转债列名：该表无 `股票代码`，正确列名为 `对应股票代码` 和 `债券名称`
- 定性问题：输出占位 SQL `SELECT '该问题涉及招股书文本内容，不在结构化数据库中' AS 提示`

### 2.4 sql_executor.py

**职责**：执行 SQL，失败时携带错误信息重新生成并重试。

**执行流程**：
```
attempt 1: 执行 initial_sql
  ├─ 成功 → 返回 (rows, sql)
  └─ 失败 → 调用 generate_sql_with_error_hint(question, failed_sql, error_msg)
              attempt 2: 执行修正后 SQL
                ├─ 成功 → 返回 (rows, sql)
                └─ 失败 → 再次生成...（最多 MAX_RETRY 次）
                            全部失败 → 抛出 SQLExecutionError
```

**说明**：重试时将错误信息原文反馈给 LLM，LLM 可据此自动修正列名错误、表别名缺失等问题。

### 2.5 answer_gen.py

**职责**：将 SQL 查询结果转换为自然语言回答。

**直接格式化策略**（优先，无 LLM 调用，无幻觉风险）：

```python
def _try_direct_format(rows):
    if not rows:
        return None
    cols = list(rows[0].keys())

    # 单行：拼接所有字段
    if len(rows) == 1:
        parts = [f"共 {v} 条" if re.search(r'count|数量', k, re.I)
                 else f"{k}：{v}"
                 for k, v in rows[0].items()]
        if len(parts) <= 6:
            return "，".join(parts)

    # 多行单列（如债券名称列表）
    if len(cols) == 1:
        items = [str(r[cols[0]]) for r in rows[:20]]
        return f"{cols[0]}：" + "、".join(items)

    # 多行两列（如排名+名称）
    if len(cols) == 2 and len(rows) <= 10:
        return "\n".join(f"{list(r.values())[0]}：{list(r.values())[1]}"
                         for r in rows)

    return None  # 复杂结果交给 LLM
```

**LLM 兜底**（仅复杂多行结果）：调用 `ANSWER_MODEL`（默认 Qwen2.5-7B），最多展示50行数据，max_tokens=256。

### 2.6 fund_agent.py

**职责**：串联完整问答流程，对外提供多种接口（同步/异步/流式）。

**结果缓存**（模块级，进程内，最多500条 FIFO）：
```python
_answer_cache: dict[str, str] = {}
_CACHE_MAX = 500

def _cache_get(q: str) -> str | None:
    return _answer_cache.get(q)

def _cache_set(q: str, ans: str) -> None:
    if len(_answer_cache) >= _CACHE_MAX:
        _answer_cache.pop(next(iter(_answer_cache)))
    _answer_cache[q] = ans
```

**预分类器实现**：
```python
def classify_question(question: str) -> str:
    for kw in _DB_KEYWORDS:
        if kw in question: return "db"
    for kw in _PROSPECTUS_KEYWORDS:
        if kw in question: return "prospectus"
    if re.search(r'\b2\d{7}\b', question): return "db"
    return "unknown"
```

**query() 完整流程（含缓存）**：
```python
def query(self, question: str) -> str:
    cached = _cache_get(question)
    if cached is not None:
        return cached                    # 命中缓存，<0.1s 返回

    if classify_question(question) == "prospectus":
        _cache_set(question, "__PROSPECTUS__")
        return "__PROSPECTUS__"

    sql  = self._call_with_429_retry(generate_sql, question, schema=schema)
    rows, final_sql = run_sql_with_retry(question, sql)
    answer = self._call_with_429_retry(generate_answer, question, rows, sql=final_sql)
    _cache_set(question, answer)
    return answer
```

**异步接口**（供工单6并发调用）：

**流式生成器**（供 app.py 和工单9实时显示进度）：
```python
def query_stream(self, question: str):
    """产出 (event_type, content) 元组
    event_type: "status" | "sql" | "answer" | "error"
    """
    cached = _cache_get(question)
    if cached is not None:
        yield "answer", cached; return

    if classify_question(question) == "prospectus":
        _cache_set(question, "__PROSPECTUS__")
        yield "answer", "__PROSPECTUS__"; return

    yield "status", "正在生成 SQL…"
    sql = self._call_with_429_retry(generate_sql, question, schema=self._get_schema())
    yield "sql", sql
    yield "status", "正在执行查询…"
    rows, final_sql = run_sql_with_retry(question, sql)
    answer = self._call_with_429_retry(generate_answer, question, rows, sql=final_sql)
    _cache_set(question, answer)
    yield "answer", answer
```

**429 限流处理**：
```python
@staticmethod
def _call_with_429_retry(func, *args, **kwargs):
    for attempt in range(3):
        try:
            return func(*args, **kwargs)
        except Exception as e:
            if "429" in str(e) and attempt < 2:
                wait = 60 * (attempt + 1)
                time.sleep(wait)
            else:
                raise
```

**模块级便捷函数**（供 app.py 直接 import）：
```python
def query_stream(question: str):   return get_agent().query_stream(question)
async def query_async(question: str) -> str: return await get_agent().query_async(question)
```

### 2.8 app.py（Gradio UI）

**关键设计**：改用 `query_stream()` 生成器驱动 Gradio 流式显示，每步进度即时刷新到界面：

```python
# 启动时预加载
get_full_schema()   # 触发 lru_cache，schema 只加载一次
get_agent()         # 单例初始化

def answer_question(question: str):
    """Gradio 生成器函数，每步 yield (answer_box, sql_box, type_box)"""
    t0 = time.time()
    answer_box = ""
    sql_box = ""

    for evt, content in get_agent().query_stream(question):
        if evt == "status":
            yield answer_box, sql_box, content          # 状态栏实时刷新
        elif evt == "sql":
            sql_box = content
            yield answer_box, sql_box, "正在执行查询…"  # SQL 框即时填入
        elif evt == "answer":
            total = time.time() - t0
            if content == "__PROSPECTUS__":
                yield "该问题涉及招股说明书内容…", "无需SQL（招股书问题）", f"招股书类（共 {total:.1f}s）"
            else:
                yield content, sql_box, f"数据库类（共 {total:.1f}s）"
        elif evt == "error":
            yield f"查询失败：{content}", sql_box, "失败"
```

**Gradio 队列**（流式必须）：
```python
demo.queue()
demo.launch(server_name="0.0.0.0", server_port=7861, ...)
```

用户体验变化：提交问题后，状态栏会依次显示 "正在生成 SQL…" → SQL 内容填入 → "正在执行查询…" → 最终答案，而非等待全部完成后一次性渲染。缓存命中时（同一问题重复提问），状态栏直接显示"共 0.0s"。
