## 二、核心模块实现

### 2.1 Agent Engine — Function Calling 循环

`backend/agent_engine.py` 是整个系统的核心，实现多轮 Function Calling：

```
用户消息加入消息链
       │
       ▼
 调用 LLM（携带 TOOLS_SCHEMA）
       │
       ├── finish_reason = "tool_calls"
       │       │
       │       ├── 防重复调用检查（同 tool+args 只调一次）
       │       ├── ToolExecutor.execute(name, args)
       │       ├── 工具结果加入消息链（role: "tool"）
       │       └── 继续循环（最多 5 轮）
       │
       └── finish_reason = "stop"
               │
               └── 流式推送 token → 客户端 / 返回完整文本
```

**关键设计：**
- `Session` 对象持有完整消息链，跨多轮保留上下文
- `_build_system_prompt()` 每次创建 Session 时动态生成，嵌入实时时间
- `called_tools_this_turn` 集合防止同一轮重复调用相同工具

### 2.2 真实 LLM Token 流

`chat_stream()` 使用 `self.llm.chat_stream()` 实现真正的逐 token 推送：

- 工具调用阶段：等待完整 tool_calls 聚合后执行，不推 token
- 文本回复阶段：每个 token 立即 yield，前端实时显示打字效果
- `llm_provider.py` 中流式聚合：跨 chunk 拼接 `tool_calls.function.arguments`

### 2.3 ToolExecutor — 4 个工具实现

| 工具 | 关键逻辑 |
|------|----------|
| `_add_schedule` | 校验必填→重复检测（同名/同时间）→写 DB；`force=true` 跳过检测 |
| `_query_schedules` | 返回 `#N [DB_ID=X] HH:MM 事项` 格式，LLM 展示时隐藏 DB_ID |
| `_update_schedule` | 仅更新传入字段，其余保持不变 |
| `_delete_schedule` | `confirmed=false` 展示详情，`confirmed=true` 执行删除；序号→DB_ID 自动映射 |

**序号与 DB_ID 映射机制：**
用户说"日程1"是显示序号，不是数据库 ID。系统通过两条线解决：
1. 查询结果格式带 `[DB_ID=X]`，LLM 从上下文记忆对应关系
2. `delete_schedule` 工具内置自动映射兜底：传入 ID 找不到时，当作序号去列表里找

### 2.4 提醒线程

`backend/reminder.py` 的 `ReminderThread` 是守护线程（daemon），每 30 秒：

1. 调用 `get_due_schedules()` 查到期未提醒日程
2. 对每条调用 `mark_reminded(id)` 写 `last_reminded`
3. 调用 `add_reminder()` 写入内存 `deque`

**5 种随机提醒话术：**
```python
"温馨提醒：「{title}」的时间到啦，主人！✨"
"主人！是时候「{title}」了喔~ 🌸"
"亲爱的主人，现在是「{title}」的时候啦！💕"
"嘿，主人，该「{title}」了哦~ ⏰"
"叮咚～「{title}」的时间到咯，别忘了呀！🎀"
```

### 2.5 前端实现

`api/static/index.html`（纯原生 JS，无框架）：

- **SSE 流式接收**：`fetch` + `ReadableStream` 逐块解析 `data: {...}` 事件
- **提醒轮询**：`setInterval(pollReminders, 15000)` 每 15 秒 GET `/api/reminders/pending`
- **提醒横幅**：滑入动画，8 秒自动消失，可手动关闭
- **浏览器通知**：`Notification API`，需用户授权
- **会话持久化**：`localStorage` 存 `session_id`，刷新页面不丢失会话

## 三、System Prompt 关键规则

| 规则 | 内容 |
|------|------|
| 规则1 | 100% 数据库调用，任何情况都调工具 |
| 规则2 | 序号 ≠ DB_ID，用户说的"1"是显示序号 |
| 规则3 | 缺必填字段必须追问，不强行调用 |
| 规则4 | 口语时间→24小时格式；竖线格式 `15:15\|0000001\|买咖啡` 正确解析 |
| 规则5 | 删除先展示确认，用户确认后再执行 |
| 规则6 | 循环日程关键词识别 → repeat_type + repeat_rule |
| 规则7 | 同一请求只调一次工具 |
| 规则8 | 已过时间的日程也正常添加 |
| 规则9 | 展示给用户时隐藏 DB_ID |
| 规则10 | title 去掉"提醒我/您/帮我"等前缀，只保留事项本身 |

## 四、数据序列化处理

PyMySQL 对不同 MySQL 类型的 Python 映射：

| MySQL 类型 | Python 类型 | 处理方式 |
|------------|------------|---------|
| DATE | `datetime.date` | `.strftime("%Y-%m-%d")` |
| TIME | `datetime.timedelta` | `total_seconds()` → `HH:MM:SS` |
| DATETIME | `datetime.datetime` | `.strftime("%Y-%m-%d %H:%M:%S")` |

TIME 字段返回 `timedelta` 是一个常见陷阱，`_serialize()` 方法统一处理所有时间类型的序列化。

## 五、线程隔离设计

| 线程 | DatabaseManager 实例 | 说明 |
|------|---------------------|------|
| FastAPI 主线程 | `db`（主连接） | 处理 API 请求 |
| ReminderThread | `_reminder_db`（独立连接） | 每30秒扫描 |

两个线程各持独立的 MySQL 连接，避免 PyMySQL 连接非线程安全导致的 `WinError 10038`。
