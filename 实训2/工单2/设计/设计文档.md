# 日程提醒智能体 — 软件设计文档

工单编号：人工智能 NLP-Agent 数字人项目-日程提醒智能体任务

---

## 一、功能需求梳理

| 功能模块 | 描述 |
|----------|------|
| 添加日程 | 自然语言输入，解析时间/事项/循环规则，存入数据库 |
| 查询日程 | 按日期/关键词/状态查询，结果按时间排序展示 |
| 修改日程 | 支持修改时间、事项、循环规则、状态 |
| 删除日程 | 搜索确认→用户二次确认→执行删除，防误删 |
| 循环日程 | 支持 daily/weekly/monthly/yearly 四种重复规则 |
| 到时提醒 | 后台线程扫描到期日程，推送到前端展示横幅+浏览器通知 |
| 重复检测 | 添加时检查同名/同时间段日程，提示用户确认 |
| 口语解析 | 将"下午5点""工作日""每月1号"等转为标准字段 |

## 三、数据库设计

### 数据库：`agent_schedule_reminder`

### 表：`schedules`

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| id | INT AUTO_INCREMENT | — | 主键，数据库真实 ID |
| title | VARCHAR(256) NOT NULL | — | 日程事项内容（纯事项名，不含"提醒我"等前缀） |
| schedule_date | DATE NOT NULL | — | 日程日期 YYYY-MM-DD |
| schedule_time | TIME NOT NULL | — | 日程时间 HH:MM:SS |
| repeat_type | VARCHAR(16) | 'none' | 重复类型：none/daily/weekly/monthly/yearly |
| repeat_rule | VARCHAR(512) | '' | 重复规则 JSON，如 `{"weekdays":[1,2,3,4,5]}` |
| status | VARCHAR(16) | 'active' | 状态：active/completed/cancelled |
| remind_before | INT | 0 | 提前提醒分钟数，0 表示准时 |
| last_reminded | DATETIME | NULL | 上次提醒时间（提醒线程写入） |
| created_at | DATETIME | NOW() | 创建时间 |
| updated_at | DATETIME | NOW() ON UPDATE | 更新时间 |

**索引设计：**
- `idx_date`：按日期查询
- `idx_status`：按状态筛选
- `idx_date_status`：联合索引，日期+状态最常用组合
- `idx_datetime`：日期+时间，提醒线程扫描用

### repeat_rule 格式规范

| repeat_type | repeat_rule 示例 | 含义 |
|-------------|-----------------|------|
| none | `""` | 不重复 |
| daily | `""` | 每天 |
| weekly | `{"weekdays":[1,2,3,4,5]}` | 周一到周五（1=周一，7=周日） |
| weekly | `{"weekdays":[6,7]}` | 周末 |
| monthly | `{"day":15}` | 每月15号 |
| yearly | `{"month":3,"day":8}` | 每年3月8日 |

## 四、Function Calling 工具设计

系统定义 4 个工具，由 LLM 根据用户意图决策调用：

| 工具名 | 触发场景 | 必填参数 |
|--------|----------|----------|
| add_schedule | 用户说"添加/记一下/提醒我" | title, schedule_date, schedule_time |
| query_schedules | 用户问"有什么日程/今天安排" | 无必填（全选） |
| update_schedule | 用户说"修改/改成/推迟/提前" | schedule_id |
| delete_schedule | 用户说"删除/取消/去掉" | confirmed |

### Function Calling 流程图

```
用户输入
   │
   ▼
LLM 理解意图
   │
   ├── 需要工具 ──→ 生成 tool_calls
   │                    │
   │                    ▼
   │              ToolExecutor 执行
   │                    │
   │                    ▼
   │             工具结果回填消息链
   │                    │
   │                    ▼
   │             LLM 生成最终回复（最多5轮）
   │
   └── 不需要工具 ──→ 直接回复
```

## 五、提醒机制设计

```
提醒线程（每30秒）
    │
    ▼
get_due_schedules()
    ├── 非循环：schedule_date = 今天 AND schedule_time <= 当前时间
    ├── daily：创建日期 ≤ 今天 AND schedule_time <= 当前时间
    ├── weekly：创建日期 ≤ 今天 AND 今天星期几 in weekdays AND schedule_time <= 当前时间
    ├── monthly：创建日期 ≤ 今天 AND 今天日期数 = rule.day AND schedule_time <= 当前时间
    └── yearly：创建日期 ≤ 今天 AND 今天月日 = rule.{month,day} AND schedule_time <= 当前时间
    共同条件：last_reminded IS NULL OR DATE(last_reminded) < 今天
    │
    ▼
mark_reminded(id)  →  更新 last_reminded = NOW()
    │
    ▼
add_reminder()  →  写入内存 reminder_queue
    │
    ▼
前端 poll /api/reminders/pending（每15秒）
    │
    ▼
弹出横幅 + 浏览器 Notification
```

**最大提醒延迟：30s（后端扫描）+ 15s（前端轮询）= 45秒**

## 六、Session 与时间上下文设计

- 每个浏览器会话维护独立的 `Session` 对象，持有完整消息链
- System Prompt 在每次创建 Session 时**动态生成**（调用 `_build_system_prompt()`），内嵌当前真实时间
- 这样 LLM 始终知道"今天是哪天"，避免时间固化问题

## 七、安全设计

- API Key 和数据库密码存放在 `.env` 文件，不提交到代码仓库
- `.gitignore` 屏蔽 `.env`
- `config.json` 只存非敏感配置项（base_url、model、db_host 等）
- 使用 `python-dotenv` 在启动时自动加载 `.env`
