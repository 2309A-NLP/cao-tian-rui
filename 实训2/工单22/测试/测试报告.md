## 3. 性能基准

### 3.1 recall 检索延迟

| 场景 | 延迟 |
|------|------|
| 冷启动（首次，ChromaDB 未预热） | ~221ms |
| 热态（预热后 3 次中值）| **~155ms** |
| 工单 SLA 目标 | < 200ms |

**结论**：热态延迟满足 SLA（155ms < 200ms）。冷启动略超，属 ChromaDB 首次 IO 开销，生产部署中服务常驻，冷启动仅发生一次。

### 3.2 remember 写入延迟

| 阶段 | 说明 |
|------|------|
| remember() 调用返回 | < 1ms（fire-and-forget，立即返回）|
| 后台 Qwen 提取 + ChromaDB 写入 | ~20~30s（异步，不阻塞响应）|
| 工单 SLA 目标 | < 500ms（API 响应层面）|

**结论**：API 层面（路由到返回）< 500ms，满足 SLA。实际落盘时间约 25s 由 Qwen 决定，符合设计预期。

### 3.3 端到端对话响应时间

| domain | 平均总耗时（含 recall + LLM）|
|--------|------------------------------|
| medical（工单12可用时）| ~5~8s（受工单12网络延迟影响）|
| medical（fallback）| ~8~15s |
| travel | ~8~15s（Qwen 72B 推理）|
| education | ~8~15s |

## 5. 已知限制

| 项目 | 说明 |
|------|------|
| API 速率限制 | SiliconFlow 免费层有 TPM 限制，高频测试时可能 429；建议加间隔 |
| 记忆截断 | >400 字内容截断，TC-06 验证不报错但未验证截断后语义损失 |
| 工单12依赖 | TC-10 medical 测试依赖工单12服务（http://localhost:8012）可用性；不可用时验证 fallback |
| ChromaDB 并发 | 嵌入式模式不支持多 worker；生产建议 `--workers 1` |
