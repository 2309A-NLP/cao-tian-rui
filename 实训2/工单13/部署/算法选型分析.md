# 工单13 - 影像分析 算法选型分析

> 工单编号：人工智能 NLP-Agent 数字人项目-医疗智能体-影像分析
> 创建时间：2026-07-06

---

## 一、任务定义与技术路线总览

本工单属于 **NLP 方向**，核心目标是用自然语言接口让患者理解医学影像。
三个子任务的技术路线均基于"多模态大模型 API 调用 + 轻量本地向量检索"，
不依赖本地 GPU，通过硅基流动平台调用云端大模型。

```
医学影像 + 自然语言问题
        ↓
  多模态 LLM（Qwen3-VL-32B）
        ↓                ↓                ↓
      VQA           MRG（报告生成）    RAG（检索增强）
   直接视觉问答    结构化 5 段报告    向量检索 + 增强回答
```

## 二、核心算法选型

### 2.1 视觉大模型（VLM）：Qwen3-VL-32B-Instruct

| 候选方案 | 优点 | 缺点 | 是否选用 |
|---------|------|------|---------|
| **Qwen3-VL-32B-Instruct（选用）** | 中文理解强，医学影像表现佳，硅基流动稳定支持 | 320亿参数推理时延 7-17s | ✅ |
| Qwen2.5-VL-72B-Instruct | 参数更大精度更高 | 硅基流动已禁用（code 30003），不可用 | ❌ |
| LLaVA-Med | 医学专用微调 | 无中文支持，无公开 API | ❌ |
| GPT-4o | 综合能力强 | 国内访问受限，成本高 | ❌ |
| 本地部署 vLLM | 无网络延迟 | 需 A100 GPU，硬件成本不可接受 | ❌ |

**选用理由**：
- Qwen3-VL 架构比 Qwen2.5-VL 更新，视觉编码器升级，中文医学文本理解更强
- 硅基流动 OpenAI 兼容协议，代码切换成本为零（只改 model name）
- 32B 参数在精度和成本之间取得平衡（72B 的 ~45% 成本，精度差距可接受）

---

### 2.2 VQA（视觉问答）

**算法**：Zero-shot Visual Question Answering（零样本视觉问答）

| 方案 | 说明 | 选用 |
|------|------|------|
| **Zero-shot VQA via VLM（选用）** | 直接用多模态大模型，无需额外训练 | ✅ |
| Fine-tuned VQA 模型（如 MedVQA） | 精度高但需标注数据和GPU训练 | ❌ |
| CLIP + 分类器 | 仅支持封闭式问答 | ❌ |

**实现要点**：
- System Prompt 规定免责声明、非医疗图片识别、低质量图片拒绝三条规则
- 图片以 base64 内联传递，避免额外文件服务器依赖
- 支持中英文双语问答（模型原生支持）

---

### 2.3 MRG（医疗报告生成）

**算法**：Template-guided Structured Report Generation（模板引导结构化报告生成）

| 方案 | 说明 | 选用 |
|------|------|------|
| **模板 JSON + VLM 填充（选用）** | 字段明确，可验证，降级策略清晰 | ✅ |
| 自由文本生成 | 灵活但无结构，难以程序验证 | ❌ |
| 本地医学报告模型（RadBERT 等） | 精度高但无中文支持 | ❌ |

**报告结构（5段）**：

```json
{
  "chief_complaint": "主诉",
  "findings":        "影像所见（详细描述）",
  "impression":      "诊断印象",
  "recommendation":  "建议",
  "disclaimer":      "免责声明"
}
```

**JSON 解析降级策略（3级）**：
1. `json.loads()` 直接解析
2. 正则提取 ` ```json ... ``` ` 代码块
3. 截取首 `{` 至末 `}` 子串
4. 三次重试仍失败 → 原始文本写入 `findings`，标记 `status=degraded`

---

### 2.4 RAG（检索增强生成）

**算法**：Caption-Augmented RAG（影像描述增强的检索增强生成）

**流程**：
```
用户图片 + query
    ↓
Step1: VLM 生成"影像描述+查询扩写"（Caption，100 token）
    ↓
Step2: sentence-transformers 编码 → ChromaDB cosine 检索 Top-5
    ↓
Step3: 若命中（score ≥ 0.5）→ 拼入 context → VLM 增强回答
        若未命中 → 退化为纯 VQA
```

#### 嵌入模型选型

| 候选 | 维度 | 语言 | 选用 |
|------|------|------|------|
| **paraphrase-multilingual-MiniLM-L12-v2（选用）** | 384 | 中+英 | ✅ |
| text-embedding-ada-002 | 1536 | 多语言 | ❌（需OpenAI API） |
| bge-large-zh | 1024 | 中文专用 | ❌（显存需求高） |
| all-MiniLM-L6-v2 | 384 | 仅英文 | ❌ |

**选用理由**：
- 支持中英双语，与 SLAKE 数据集（中文 QA）完全匹配
- 384 维轻量，ChromaDB 内存占用 < 500MB
- 无 GPU 需求，CPU 推理 < 100ms

#### 向量数据库选型

| 候选 | 特点 | 选用 |
|------|------|------|
| **ChromaDB（选用）** | 本地部署，Python 原生，无需额外服务 | ✅ |
| Milvus | 高性能，适合亿级数据 | ❌（本项目千级数据，过重） |
| FAISS | 纯内存，无持久化 | ❌（无元数据过滤） |
| PGVector | PostgreSQL 插件 | ❌（依赖 PG，部署复杂） |

**选用理由**：工单 NLP 方向知识库规模约千条，ChromaDB 的 HNSW 索引完全满足，且零运维成本。

#### 知识库内容

来源：SLAKE 数据集（Stanford-Leiden-Affiliated Korean Evaluation）
- 总计：~1081 条中文医学影像 QA 对（去重后）
- 字段：模态、部位、问题、答案
- 覆盖：CT / MRI / X-Ray，胸部 / 腹部 / 头部等多个部位

## 三、非功能算法决策

### 3.1 图像验证（本地，无 AI）

使用 **Pillow** 做 3 级检验：
1. `Image.verify()` —— 文件完整性
2. 分辨率检查 —— 拒绝 < 32×32
3. 格式白名单 —— 仅 JPEG / PNG（DICOM 需预转换）

**不选用**：深度学习图像质量评估（IQA），成本高、延迟大，PIL 已足够。

### 3.2 隐私保护

一期方案：仅在响应中附加免责声明，不做 EXIF 数据剥离。
原因：EXIF 在 base64 传输场景对用户隐私的实际风险可控，二期可加 `piexif` 去除。

## 五、选型决策摘要

| 决策点 | 选择 | 核心理由 |
|--------|------|---------|
| VLM | Qwen3-VL-32B via 硅基流动 | 中文医学最优 + 无 GPU 需求 |
| 嵌入模型 | MiniLM-L12 多语言版 | 中英双语 + 轻量 CPU |
| 向量库 | ChromaDB | 千级数据无需重型基础设施 |
| RAG 策略 | Caption 增强检索 | 纯文本 query 无法描述影像特征 |
| MRG 策略 | JSON 模板 + 3 级降级 | 结构可验证，鲁棒性强 |
