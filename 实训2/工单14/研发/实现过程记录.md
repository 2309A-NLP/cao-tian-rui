API Server 的关键：
- 用 `lifespan` 事件管理 `MCPClientPool` 生命周期
- 前端 REST 快捷通道（`/api/amap/hospital` 等）内部走 `pool.call()`，与 Agent 共用同一 MCP 通道，避免两套逻辑

## 二、关键技术决策与理由

### 决策 1：HTTP 代理 vs 进程内 import

**选择**：HTTP 代理

| 维度 | HTTP 代理 | 进程内 import |
|---|---|---|
| 耦合度 | 低 | 高 |
| 上游改包结构 | 无影响 | 每次同步改 |
| 独立 venv | 支持 | 依赖冲突严重 |
| 未来容器化 | 每工单一个容器 | 需要合并 venv |
| 单次调用开销 | ~10ms | ~0ms |

选 HTTP 代理，10ms 的开销换来解耦是划算的。

### 决策 2：MCP 协议全流程使用官方 SDK

**选择**：`mcp[cli]==1.28.1`（Anthropic 官方 Python SDK）

理由：兼容 Claude Desktop / Cursor / Cline / n8n 等主流 MCP 客户端，长期可维护。手写 JSON-RPC 会失去生态。

### 决策 3：高德对接不用官方 SSE MCP

**选择**：自建 `amap_mcp` 直接调高德 Web REST API

理由（详见 [docs/高德MCP对接文档.md](高德MCP对接文档.md)）：
- 官方 SSE 需要稳定长连接，本地开发不便
- 我们的业务组合 tool（`nearby_hotels(hospital="xxx")` 一步完成"搜医院→搜周边"）比原子接口更好用
- Key 存 `.env`，不出现在 URL

保留兼容路径：`.env` 里的 `AMAP_MCP_URL` 已预留。

### 决策 4：未开工工单的占位方案

**选择**：接口签名真实 + `/health` 探测自动切换

工单 03/05 未开工时，`imaging_mcp` / `voice_mcp` 会先 GET `http://localhost:8013/health`（300ms 超时，优化后），若通则真的转发，否则返回 `{status: "not_implemented", ...}`。

好处：
- 上游一旦跑起来，不用改 MCP 代码
- Agent 能感知"能力暂不可用"，礼貌回复用户
- 前端交互仍可流转

### 决策 5：前端 Alpine.js CDN

新原型有双面板 + 4 类 tab + 状态切换，vanilla JS 手写会很啰嗦，但引入 Vue3 + Vite 又太重。Alpine.js 3KB CDN，`x-data / x-show / x-for` 学 5 分钟能写，正合适。

## 三、实际遇到的坑与解决

### 坑 1：`requirements.txt` 中文注释导致 pip GBK 解码失败

**现象**：Windows PowerShell 里跑 `pip install -r requirements.txt` 报错：

```text
UnicodeDecodeError: 'gbk' codec can't decode byte 0x8e in position 35: illegal multibyte sequence
decoding with 'cp936' codec failed
```

**原因**：`requirements.txt` 是 UTF-8 编码（含中文注释），pip 在 Windows 中文环境下用系统默认 GBK/CP936 解码，遇到 UTF-8 多字节序列报错。

**修复**：把注释改成纯英文 ASCII。

**教训**：Windows 环境下工程配置文件（尤其被系统命令读取的）尽量纯 ASCII。

### 坑 2：stdio Server 长连接管理

**问题**：如果每次调用 tool 都重开 stdio 子进程，5 个 Server 的启动开销累积极高。

**解决**：`MCPClientPool` 用 `AsyncExitStack` 集中管理 5 个 `ClientSession` 的生命周期：

```python
async with AsyncExitStack() as stack:
    for name in SERVERS:
        read, write = await stack.enter_async_context(stdio_client(params))
        session = await stack.enter_async_context(ClientSession(read, write))
        await session.initialize()
        self.sessions[name] = session
    yield  # 保持连接
```

FastAPI 里通过 `lifespan` 事件把 pool 挂到 `app.state`，全局单例。

### 坑 3：`_AMapSecurityConfig` 必须在 AMap JS 加载前

**问题**：先加载 `<script src="webapi.amap.com/maps?...">` 再设置 `window._AMapSecurityConfig`，控制台报安全码错误、地图空白。

**解决**：把 `window._AMapSecurityConfig = {...}` 放在动态加载 AMap JS 之前：

```javascript
async init() {
    const cfg = await fetch('/api/amap/js-config').then(r=>r.json());
    window._AMapSecurityConfig = { securityJsCode: cfg.security_js_code };  // 必须先
    await this.loadAMap(cfg.js_key);                                        // 后加载
    this.initMap();
}
```

### 坑 4：LLM function calling 的 tool_name 命名冲突

**担忧**：5 个 Server 若有同名 tool（如都叫 `search`），LLM 会歧义。

**预防**：设计时保持全局唯一命名（`hospital_search / query_slots / analyze_image / transcribe / ...`），无需前缀。评测结果 20/20 命中，说明命名清晰度足够。

### 坑 5：路线规划的坐标 vs 地名

**问题**：`route_planning(origin="西直门", destination="北京协和医院")` 直接送到高德 direction/driving 接口会报错（那个接口只接受 `lng,lat` 坐标）。

**解决**：`amap_mcp._geocode()` 内部先把非坐标格式的起终点转成坐标，并通过 `asyncio.gather()` 并发获取双端坐标：

```python
if not origin_is_coord and not dest_is_coord:
    o, d = await asyncio.gather(
        _geocode(client, origin, city),
        _geocode(client, destination, city)
    )
    origin, destination = o["location"], d["location"]
```

### 坑 6：LLM 抽取参数时可能漏值

**问题**：query "百日咳有什么症状"，LLM 调 `health_consultation` 时可能不传 `patient_id`。

**解决**：所有 tool 的可选参数都给默认值（`patient_id: str = "default_patient"`）。Python 层兜底，LLM 不必传全。

### 坑 7：测试脚本 Windows GBK 终端 UnicodeEncodeError

**问题**：脚本打印 `✓`（U+2713）时 PowerShell 报 `'gbk' codec can't encode character`，脚本崩溃。

**修复**：4 个测试文件开头统一加：

```python
if hasattr(sys.stdout, "reconfigure"):
    sys.stdout.reconfigure(encoding="utf-8", errors="replace")
```

### 坑 8：imaging/voice 上游探测超时 2s 导致工具时延 3s+

**问题**：上游未开工时，`_upstream_alive()` 等待 `httpx.AsyncClient(timeout=2.0)` 超时，每次调用浪费 2 秒。

**修复**：超时从 2.0s 改为 0.3s。本地 `/health` 端点若 300ms 内无响应，继续等待无意义。

### 坑 9：端口被上次进程占用（WinError 10048）

**问题**：重启服务时报 `error while attempting to bind on address: [WinError 10048]`，原因是上次进程未正常退出仍占用端口。

**修复**：`run.ps1` 加入 `KillPort` 函数，每次启动前自动释放端口；`stop.ps1` 一键停止所有服务。

```powershell
# 一键停止后重启
cd "F:\kimi  project\医疗agent1"; .\stop.ps1; .\run.ps1
```
