## 三、遇到的问题与解决

### 问题 1：pip 安装时 UnicodeDecodeError

**现象**：
```
UnicodeDecodeError: 'gbk' codec can't decode byte 0x8e in position 35
decoding with 'cp936' codec failed
```

**原因**：`requirements.txt` 最初含中文注释（UTF-8 编码），pip 在 Windows 中文系统默认用 GBK/CP936 解码，遇到 UTF-8 多字节序列报错。

**解决**：将 `requirements.txt` 中所有注释改为纯英文 ASCII。

**教训**：Windows 环境下被系统命令读取的配置文件（`requirements.txt`、`.bat` 脚本等）必须使用纯 ASCII，不得含中文。

---

### 问题 2：测试脚本 UnicodeEncodeError

**现象**：运行 `eval_routing.py` / `eval_robustness.py` 时：
```
UnicodeEncodeError: 'gbk' codec can't encode character '✓'
```

**原因**：脚本用 `✓`（U+2713）、`✗`（U+2715）等 Unicode 字符打印到终端，PowerShell 默认 GBK 编码无法表示这些字符。

**解决**：在每个测试脚本开头添加：
```python
if hasattr(sys.stdout, "reconfigure"):
    sys.stdout.reconfigure(encoding="utf-8", errors="replace")
```

已修复的文件：`tests/eval_routing.py`、`tests/eval_robustness.py`、`tests/eval_performance.py`、`tests/demo_thinking.py`。

**教训**：Windows PowerShell 终端默认 GBK，Python 脚本若有 Unicode 输出必须显式设置 stdout 编码。

---

### 问题 3：MCP Server 子进程启动失败（概率性）

**现象**：偶尔某个 MCP Server 在 Pool 初始化时卡住，超时后整体失败。

**原因**：`sys.executable -m mcp_servers.xxx_mcp` 启动时，若当前工作目录不对，模块找不到 `.env`，会尝试连接默认配置并卡在网络超时。

**解决**：`MCPClientPool` 中启动子进程时明确传入 `cwd=_ROOT`（项目根目录）和 `PYTHONPATH=_ROOT`，确保 `.env` 和模块路径均正确。

---

### 问题 4：_AMapSecurityConfig 必须在 AMap JS 加载前设置

**现象**：地图空白，控制台报"JS API 安全码校验失败"。

**原因**：代码先加载了 `<script src="webapi.amap.com/maps">` 再设置 `window._AMapSecurityConfig`，顺序颠倒。

**解决**：前端 `init()` 先 `fetch('/api/amap/js-config')` 获取 Key，设置 `window._AMapSecurityConfig`，再动态创建 `<script>` 加载 AMap JS：
```javascript
const cfg = await fetch('/api/amap/js-config').then(r => r.json());
window._AMapSecurityConfig = { securityJsCode: cfg.security_js_code };
await this.loadAMap(cfg.js_key);
```

### 联通 00 门户

00 门户（`F:\kimi project\医疗agent1\00-总界面框架\index.html`）已修改，"出行服务"模块通过 iframe 加载 8014：
