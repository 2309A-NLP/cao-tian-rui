## 一、需求概述

### 1.1 业务背景
患者就医不仅仅是挂号和问诊，还涉及出行规划、住宿安排、餐饮选择等周边服务。特别是异地就医患者，对医院周边信息需求强烈。本模块通过 **对接高德地图 MCP Server**，将地图服务能力融入医疗 Agent，实现医院位置查询、路线规划、周边服务搜索等功能。

### 1.2 目标用户
- **主要用户**: 需要前往医院就诊的患者及家属
- **特别是**: 异地就医、首次就诊、带老人/儿童就诊的用户
- **使用场景**: 出行前规划、到达后寻找周边服务

### 2.2 业务流程

#### 医院位置查询
```
用户: 北京儿童医院在哪里?
    |
    v
Agent 调用高德地图 MCP: 地点搜索（北京儿童医院）
    |
    v
返回: 地址、坐标、电话、营业时间
    |
    v
展示地图卡片 + 详细信息
```

#### 出行规划
```
用户: 从我家开车去协和医院要多久?
    |
    v
Agent 解析起点（用户家庭地址/当前位置）+ 终点（协和医院）
    |
    v
调用高德 MCP: 路线规划（驾车，起点->终点）
    |
    v
返回: 多条路线、距离、预计时间、过路费、路况
    |
    v
展示路线卡片（推荐路线高亮）
```

#### 周边服务
```
用户: 协和医院附近有什么干净的酒店?
    |
    v
Agent 调用高德 MCP: 周边搜索（协和医院坐标，酒店，排序=评分）
    |
    v
返回: 酒店列表（名称、距离、评分、价格区间）
    |
    v
展示酒店卡片列表，支持筛选和排序
```

## 三、MCP 架构设计

### 3.1 MCP Server 设计

> **说明**：本工单要求的"TOOL 封装成 MCP Server"，指的是把**新目录下 01/02/03/05 各工单的能力**封装为 MCP Server，
> 而不是重复造高德地图 tool（那已经由高德官方 MCP Server 直接提供）。
> 我们采用 **HTTP 代理型** 封装：每个上游工单跑自己的 FastAPI 服务，MCP Server 用 httpx 调它的 REST 接口。
> 理由：解耦、上游改包结构不影响 MCP、各工单独立 venv 独立启动。

| MCP Server | 上游 | 状态 | 暴露的 Tool |
|---|---|---|---|
| `registration_mcp` | 工单01（8011） | 🟡 推进中，接口稳定 | `chat_registration` / `query_slots` / `get_appointments` / `get_doctor_schedule` |
| `knowledge_mcp` | 工单02（8012） | 🟢 接近完成 | `health_consultation` / `graph_stats` |
| `amap_mcp` | 高德官方 SSE MCP | ✅ 直接对接 | 高德官方工具集（POI/路线/周边） |
| `imaging_mcp` | 工单03（8013） | 🔴 未开工，**接口占位** | `analyze_image` / `generate_report` → 返回 not_implemented |
| `voice_mcp` | 工单05（8015） | 🔴 未开工，**接口占位** | `transcribe` → 返回 not_implemented |

## 五、非功能需求

### 5.1 性能要求
- 地图加载 < 2s
- 地点搜索 < 500ms
- 路线规划 < 1s

### 5.2 质量要求

> 原稿"位置精度 99% / 路线合理性 90% / 相关性 85%" 均属高德底层能力或主观项，无法客观验收。
> 收敛为**可量化的、我们能控制的指标**：

- 高德 API 调用可用性 >= 99%（网络/超时兜底）
- **路由意图分类精度 >= 80%**（对应工单验收"检索精度 ≥ 80%"）
- 周边搜索 Top10 结果距离目标医院 <= 3km 的占比 = 100%（高德 API 参数约束）
- 未开工工单（03/05）的意图能被识别，并返回明确的"暂未开放"提示（不误路由到其他 Server）
