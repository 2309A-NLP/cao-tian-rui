## 二、发现问题清单

### F1 · 中【✅ 已修复 2026-07-06】SSRF 风险 — `tool_fetch.py:33`

**问题：** `web_fetch()` 对传入的 URL 不做任何校验，直接发起请求，且允许跟随重定向（`allow_redirects=True`）。

**触发场景：** 若搜索结果中出现指向内网地址的 URL（如 `http://192.168.1.1/admin`、`http://localhost:8023/health`），Qwen 调用 `fetch(url)` 时会访问内网资源，响应内容会被 LLM 看到。

**影响：** 内网信息泄露；在 PAI-EAS 云环境部署后风险更高（云内网服务可访问）。

**已修复：** `tool_fetch.py` 新增 `_is_safe_url()` 函数，覆盖 127.x / 10.x / 172.16.x / 192.168.x / 169.254.x 及 IPv6 私有段；`web_fetch()` 开头检测，命中则直接返回 `success=False`，不发起请求。域名解析失败时放行（由 requests 正常超时处理）。

---

### F2 · 低【✅ 已修复 2026-07-06】工单合规 C7 部分缺失 — `answer_generator.py:103`

**问题：** `_needs_normalization()` 只检测"中文题但答案英文太多"，未检测"英文题但答案中文太多"的反向情形。

**触发场景：** 英文题（如 `"Who won the 2024 Paris Olympics 100m?"`)，若 IQS 返回中文搜索结果，Qwen 可能用中文作答，不触发归一化，违反 C7。

**当前代码：**
```python
if meta.lang == "zh":          # 只处理中文题
    zh_count = ...
    en_count = ...
    if en_count > 10 and zh_count < en_count * 0.3:
        return True
return False
```

**已修复：** `answer_generator.py:_needs_normalization()` 在现有 `if meta.lang == "zh"` 块后追加：
```python
elif meta.lang == "en":
    zh_count = len(re.findall(r"[一-鿿]", answer))
    if zh_count > 5:
        return True
```
英文题答案若含 >5 个中文字符则触发 LLM 归一化，补全 C7 双向检测。

### F3 · 低【逻辑】强制搜索后 rounds_used 计数偏差 — `react_loop.py:71`

**问题：** 第1轮触发强制搜索后 `continue`，进入第2轮循环，`rounds_used` 最终记录的是"第几次 LLM Think 调用"而非"实际发生了几轮搜索"。用户在前端看到"1轮"实际已搜索了1次。

**影响：** 仅影响前端显示计数，不影响答案正确性，属于轻微显示问题。

**当前行为：** 强制搜索发生在 round_num=1，`continue` 后进入 round_num=2，最终 `rounds_used=2` 但实际搜索了2次（强制1次+正常1次），计数本身是准确的，只是日志里"Round 1 final answer"可能引起混淆。

**结论：** 逻辑实际正确，计数无误。仅日志措辞可优化。

---

### F4 · 信息【状态存储线程安全】_status_store 并发写 — `app.py:30`

**问题：** `_status_store` 是普通 dict，虽然 `_set_status` 用 Lock 保护，但 `get_status` 端点直接读 `_status_store.get(req_id, {})` 在锁外执行。

**触发场景：** 高并发（多用户同时提问）时，读线程可能读到写线程写一半的状态。

**实际影响：** Python dict 单次 `.get()` 是原子操作（GIL 保护），读到旧值的概率极低，且状态数据仅用于前端进度展示，读到旧值最多显示上一个状态，不影响答案。

**修复方案（可选，低优先级）：** 在 `get_status` 视图函数里同样加锁：
```python
@app.get("/api/v1/status/<req_id>")
def get_status(req_id):
    with _status_lock:
        status = dict(_status_store.get(req_id, {}))
    return jsonify(status)
```

---

### F5 · 信息【CORS 策略宽松】Access-Control-Allow-Origin: * — `app.py:44`

**问题：** 所有响应头加了 `*`，包括 `/api/v1/status/<req_id>` 端点，任意网页可轮询查询状态。

**实际影响：** 状态数据仅含 `round/action/query/done`，无敏感信息。该服务无认证机制，本地开发场景下 `*` 是标准做法。PAI-EAS 部署后由平台网关鉴权，CORS 策略影响有限。

**结论：** 当前场景（本地+PAI-EAS）可接受，无需立即修复。
