# 金融问答系统 Docker 部署 — 详细安装步骤（可手动复现）

> 工单10。本文档提供从零到跑通的**完整、可逐步复现**的部署步骤。
> 环境：Windows 11 + Docker Desktop（已验证）。Linux 服务器同理，路径写法改为 Linux 风格即可。

---

## 0. 环境准备（前置条件）

| 项 | 要求 | 验证命令 |
|----|------|---------|
| Docker Desktop | 已安装并运行（含 docker compose v2） | `docker --version` / `docker compose version` |
| 项目代码 | 本项目根目录（含 backend/ api/ run_api.py） | `ls Dockerfile docker-compose.yml` |
| BGE-M3 模型 | 本地模型目录（约 4.3G） | 目录内含 `config.json`、`pytorch_model.bin` 等 |
| 网络 | 能访问 LLM API（SiliconFlow / DeepSeek） | — |
| 内存 | 建议 ≥ 8G 可用（Milvus 较吃内存） | — |

> 本部署默认 **CPU 版**（无需 GPU、无需 nvidia-container-toolkit），换台机器也能跑。

## 1. 确认部署文件

项目根目录应包含以下文件（本次已生成）：

```
Dockerfile              # rag-app 镜像定义（CPU 版）
docker-compose.yml      # 6 服务编排
.dockerignore           # 构建上下文裁剪
config.docker.json      # 容器内运行配置（host 指向服务名）
.env.example            # 部署变量模板
requirements.txt        # 已锁定 pymilvus<2.5 / transformers<5
```

检查：
```bash
ls -1 Dockerfile docker-compose.yml .dockerignore config.docker.json .env.example
```

---

## 2. 准备 `.env`（关键配置）

复制模板并按你的机器修改：
```bash
cp .env.example .env
```

编辑 `.env`：
```ini
# 宿主机 BGE-M3 模型目录（Windows 用正斜杠 /）
MODEL_PATH=F:/4--专业所有安装的软件及改动设置/2-6--专高6/bge-m3

# 对外端口
APP_PORT=8010

# 检索模式：fulltext(默认,最稳) / vector / hybrid
APP_RETRIEVAL_MODE=fulltext

# LLM（DeepSeek 官方欠费时用 SiliconFlow，OpenAI 兼容端点）
APP_LLM_PROVIDER=openai
APP_LLM_API_KEY=sk-你的key
APP_LLM_BASE_URL=https://api.siliconflow.cn/v1
APP_LLM_MODEL=deepseek-ai/DeepSeek-V3
```

> ⚠️ 模型路径含中文一般可用；若挂载失败，把模型拷到纯英文路径再改 `MODEL_PATH`。
> ⚠️ `.env` 含密钥，已在 `.gitignore` 中，不会进版本库。

## 3. 确认数据已就绪（fulltext 模式依赖）

fulltext 模式的 BM25 索引在容器启动时从 `output/chunks/all_chunks.json` 构建。确认该文件存在：
```bash
ls -lh output/chunks/all_chunks.json    # 约 18M，含 18443 个文档块
```
> 该文件随项目提供。若没有，需先用项目的 PDF 处理流程生成（见架构文档第 4 节）。

---

## 4. 构建镜像

```bash
docker compose build rag-app
```

构建分层（关键设计）：
1. 装 CPU 版 torch（`--index-url .../whl/cpu`，避免拉 CUDA 大包）
2. 装 requirements（pymilvus 2.4.x / transformers 4.x）
3. **升级 torch 到 2.6.0**（transformers 4.57 加载 BGE-M3 需要）
4. COPY 代码 + 配置

> 首次构建较久（依赖下载，慢网下 ~20-30 分钟）；之后改代码只重跑 COPY 层（秒级）。
> 完成后镜像约 3.3G：`docker images rag-app:cpu`

---

## 5. 启动全栈

```bash
docker compose up -d
```

启动顺序自动编排：etcd/minio → milvus、mysql、redis（等 healthy）→ rag-app。

查看状态（等到 rag-app 变 healthy，首次约 1-2 分钟，含模型加载 + BM25 构建）：
```bash
docker compose ps
```
期望：
```
NAME         STATUS                   PORTS
rag-app      Up (healthy)             0.0.0.0:8010->8010/tcp
rag-etcd     Up
rag-milvus   Up (healthy)
rag-minio    Up
rag-mysql    Up (healthy)
rag-redis    Up (healthy)
```

> 只有 rag-app 暴露 8010；milvus/mysql/redis 仅内网，不与宿主已有容器端口冲突。

查看启动日志确认就绪：
```bash
docker compose logs rag-app | grep -E "BM25 索引构建完成|资源初始化完成|Uvicorn running"
```
应看到 `BM25 索引构建完成: 18443 个文档`、`Application startup complete`。

## 6. 访问与验证

### 6.1 浏览器访问
打开 **http://localhost:8010** ，在输入框提问（带公司名更准确）：
- 「兴图新科的注册资本是多少？」→ 应答「5,520万元 [第37页]」
- 「招商证券2021年的营业总收入是多少？」

> Docker Desktop 里点 rag-app 那行的 `8010:8010` 链接也能直接打开。

### 6.2 命令行验证（验收用）

**健康检查：**
```bash
curl http://localhost:8010/api/health
# 期望：{"status":"ok",...,"database":true,"redis":true,...}
```

**端到端问答（计时）：**
```bash
# Windows bash 下中文用文件传 body，避免编码问题
python -c "import json;open('q.json','w',encoding='utf-8').write(json.dumps({'query':'兴图新科的注册资本是多少？','mode':'rag'},ensure_ascii=False))"
curl -s -X POST http://localhost:8010/api/ask -H "Content-Type: application/json" --data-binary @q.json -w "\nHTTP %{http_code} 耗时 %{time_total}s\n"
```
期望：HTTP 200，< 3s，答案正确，含 15 条来源。

## 8. 常用运维命令

```bash
docker compose logs -f rag-app       # 跟踪日志
docker compose stop                  # 停止（保留数据）
docker compose up -d                 # 再次启动
docker compose up -d --build rag-app # 改了 Python 代码后重建生效
docker compose down                  # 删除容器（保留卷/数据）
# 注意：docker compose down -v 会删除数据卷，谨慎使用！
```

> 改**代码**（.py/前端）→ 需 `--build` 重建；改**数据**（output/knowledge_base）→ 直接生效（必要时 `restart`）。

## 9. 常见问题（实测踩坑与解法）

| 现象 | 原因 | 解决 |
|------|------|------|
| 构建装到 pymilvus 3.0 / transformers 5.x | requirements 用 `>=` 拉到大版本 | 已在 requirements 锁 `<2.5`/`<5` |
| 启动报 `require torch>=2.6` | transformers 4.57 加载 .bin 需 torch≥2.6 | Dockerfile 已追加升级 `torch==2.6.0` |
| LLM 报 402 Payment Required | DeepSeek 官方 key 欠费 | `.env` 切 SiliconFlow（`APP_LLM_*`） |
| 流式答案中文乱码 | requests 对 SSE 按 Latin-1 解码 | 已修 `llm_provider.py` 设 `encoding=utf-8` |
| 前端"知识库为空 / 向量:0" | fulltext 模式 Milvus 空（正常） | 问答仍走 BM25，可用；如需非零见第 10 节 |
| milvus 退出码 137 | 内存不足被杀 | 加大 Docker 内存；`docker compose up -d` 重启 |
| 模型挂载失败 | 中文路径/盘符未共享 | 模型挪纯英文路径；Docker Desktop 开启该盘共享 |

## 10. 可选：启用向量检索 / hybrid（让"知识库"非空）

默认 fulltext 已能问答。若要启用语义向量检索（面板显示真实向量数）：

```bash
# 在容器内用挂载的 all_chunks.json 灌入 Milvus（CPU 较慢，一次性）
docker compose exec rag-app python backend/rebuild_unified_index.py --yes
# 改 .env：APP_RETRIEVAL_MODE=hybrid，然后重启
docker compose up -d rag-app
```
> CPU 上嵌入 18443 块约需 30-60 分钟；建议有 GPU 时在宿主环境预建后再用。
