## 1. 系统简介

本系统在原有 RAG 智能问答基础上，集成了 **LightRAG 知识图谱检索**能力。通过从招股说明书 PDF 中自动抽取实体关系，构建金融领域知识图谱（5479 节点、6968 边），并提供多种检索模式（local/global/hybrid），与标准 RAG 形成互补。

### 核心亮点

| 特性 | 说明 |
|------|------|
| 知识图谱检索 | 实体-关系图谱，支持多跳推理 |
| 双模式问答 | 前端一键切换 RAG / LightRAG |
| RAGAS 评估 | faithfulness、answer_relevancy、answer_correctness |
| 故障转移 LLM | DeepSeek → SiliconFlow 自动备援 |
| GPU 加速 | BGE-M3 embedding 在 cuda:0 运行 |

## 4. 构建知识图谱

> **注意：** 知识图谱已预先构建完成（`backend/lightrag_storage_prospectus/`），通常无需重新构建。仅在添加新文档或清空存储时才需重建。

### 4.1 激活 GPU 环境

```bash
conda activate gpu_env
cd "E:\10--agent--任务\任务 1\backend"
```

### 4.2 运行建图脚本

```bash
# 构建招股说明书1 + 招股说明书2 的知识图谱
python build_lightrag.py \
    --pdfs knowledge_base/招股说明书1-无水印.pdf \
           knowledge_base/招股说明书2--无水印.pdf \
    --working-dir lightrag_storage_prospectus
```

### 4.3 建图进度说明

| 阶段 | 预计耗时 | 说明 |
|------|---------|------|
| PDF 文本提取 | 1-2分钟 | 两份文档约700页 |
| 文本分块 | < 30秒 | 生成约1474个chunk |
| 实体抽取 | 30-60分钟 | DeepSeek LLM逐批处理，有缓存 |
| 向量化 | 5-10分钟 | BGE-M3 在 cuda:0 |
| 图谱写入 | < 1分钟 | 写 .graphml + KV + VDB |

> **提速技巧：** 若遇到 DeepSeek 限速，故障转移链会自动切至 SiliconFlow，建图不会中断。

### 4.4 验证图谱完整性

```bash
python -c "
import networkx as nx
G = nx.read_graphml('lightrag_storage_prospectus/graph_chunk_entity_relation.graphml')
print(f'节点数: {G.number_of_nodes()}, 边数: {G.number_of_edges()}')
"
# 预期输出：节点数: 5479, 边数: 6968
```

## 5. 使用 LightRAG 问答

### 5.1 前端切换到 LightRAG 模式

1. 登录系统（http://localhost:8010）
2. 侧边栏找到 **"知识库来源"** 选择器
3. 将默认的 `RAG（BM25/向量）` 切换为 `⚡ LightRAG 知识图谱`
4. 在聊天框输入问题，点击发送

### 5.2 推荐问题类型

LightRAG 在以下类型问题上优于标准 RAG：

| 问题类型 | 示例 | 原因 |
|---------|------|------|
| 实体关联 | "力源信息的控股股东是谁，持股比例多少？" | 图谱直接存储实体关系 |
| 多跳推理 | "兴图新科的主要供应商提供哪些领域的产品？" | 图遍历自然支持 |
| 跨文档关联 | "两家公司都进入了哪些相同的行业？" | 共享实体节点自动关联 |
| 宏观问题 | "两家公司所处行业的主要上游有哪些？" | Global模式聚合全局信息 |

### 5.3 检索模式说明

前端目前使用 `hybrid`（本地+全局双路融合），是效果与速度的最佳平衡点。

## 6. 运行评估对比

### 6.1 LightRAG 评估（含 RAGAS）

```bash
conda activate gpu_env
cd "E:\10--agent--任务\任务 1\backend"

# 跑16题 hybrid 模式评估，包含 RAGAS 评分
python eval_lightrag.py --modes hybrid --ragas --out output
```

**参数说明：**

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--modes` | hybrid mix naive | 评估哪些模式 |
| `--ragas` | 关闭 | 加上后调用DeepSeek跑RAGAS评分 |
| `--out` | output | 结果输出目录（相对于backend/）|
| `--limit` | 0（全部）| 只测前N题（调试用）|

**预计耗时：**
- 16题问答：约 30 秒（利用 LLM 缓存，大部分直接命中）
- RAGAS 评分：约 3-5 分钟（需调用 DeepSeek 评判每道题）

**结果文件：** `backend/output/lightrag_eval_hybrid_{时间戳}.json`

### 6.2 RAG 基线评估（含 RAGAS）

```bash
# 在 gpu_env 中运行（需要 BGE-M3 做 RAGAS embedding）
conda activate gpu_env
cd "E:\10--agent--任务\任务 1\backend"

python eval_quick.py --ragas
```

**预计耗时：**
- 16题问答：约 2-3 分钟（每题需调用 RAG API）
- RAGAS 评分：约 3-5 分钟

**结果文件：** `backend/output/eval_results.json`

### 6.3 评估结果文件结构

```
backend/output/
├── eval_results.json               # RAG最新评估（含RAGAS分数）
├── eval_history/                   # RAG历史评估记录
│   └── eval_{时间戳}.json
├── lightrag_eval_hybrid_{ts}.json  # LightRAG评估（含RAGAS分数）
├── lightrag_eval_mix_{ts}.json
└── lightrag_eval_naive_{ts}.json
```

### 7.2 面板功能说明

**Tab 1：指标汇总**

6 张卡片展示两套系统的核心指标对比：

| 指标卡 | RAG 数据来源 | LightRAG 数据来源 |
|--------|------------|----------------|

| 正确率 (Answer Correctness) | ragas.answer_correctness | summary.ragas.answer_correctness |

评估面板数据是静态的（反映上次评估结果）。更新数据需重新运行评估脚本，**刷新页面**后重新打开面板即可看到最新结果。

## 8. 常见问题 FAQ

### Q1: 打开 LightRAG 模式后提示"初始化失败"？

**原因：** LightRAG 实例延迟初始化，第一次调用需要加载图谱（约 8-10 秒）。

**解决：** 等待约 10 秒后重试，或查看 docker logs：
```bash
docker logs rag-app --tail 50
```

---

### Q2: 评估面板显示"暂无评估结果数据"？

**原因：** 还没有运行过评估脚本，`backend/output/` 目录下没有对应 JSON 文件。

**解决：**
```bash
conda activate gpu_env
cd "E:\10--agent--任务\任务 1\backend"
python eval_lightrag.py --modes hybrid --ragas --out output
python eval_quick.py --ragas
```

---

### Q3: RAGAS 评分运行时报 "Invalid n value"？

**原因：** DeepSeek API 不支持 `n>1`，RAGAS 默认 `strictness=3` 会请求 `n=3`。

**解决：** 代码已修复（`answer_relevancy.strictness = 1`），若仍报错请检查 ragas 版本：
```bash
pip show ragas
```
如果是旧版本，升级：`pip install ragas --upgrade`

---

### Q4: 建图时 DeepSeek 频繁报 429 限速？

**原因：** DeepSeek 官方 API 有 QPS 限制。

**解决：** 代码内置故障转移链会自动切至 SiliconFlow，无需手动干预。若两个 API 都不通，检查 `.env` 中的 API Key 是否有效：
```bash
cat "E:\10--agent--任务\任务 1\.env"
```

---

### Q5: BGE-M3 报 "CUDA out of memory"？

**原因：** GPU 显存不足（BGE-M3 需约 4GB VRAM）。

**解决方案：**
1. 关闭其他占用 GPU 的进程
2. 修改 `lightrag_integration.py` 改用 CPU：`device="cpu"`（速度变慢但可用）
