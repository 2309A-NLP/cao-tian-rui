# RAG vs LightRAG 评估体系与测试报告

> 版本：v1.0 | 测试日期：2026-06-18  
> 工单：实训1 · 工单14 · LightRAG 优化集成

---

## 一、评估维度

### 1. 回答准确率（Answer Accuracy）

衡量系统回答是否包含正确的关键事实。评估方法为关键词命中检测，每题预设 `answer_keywords` 列表，命中达到阈值（通常 ≥ 60%）则为通过（pass）。

### 2. RAGAS 三项指标

| 指标 | 英文 | 定义 | 计算方式 |
|------|------|------|---------|
| 忠实度 | Faithfulness | 回答声明是否可从检索上下文推导 | 将回答拆成claim，逐条验证是否有文档支持 |
| 相关性 | Answer Relevancy | 回答与问题的相关程度 | 从回答逆向生成问题，与原问题计算向量相似度 |
| 正确率 | Answer Correctness | 回答与参考答案的匹配度 | 语义相似度 × 事实覆盖率的加权组合 |

### 3. 检索证据覆盖率（Context Recall）

衡量检索到的上下文是否覆盖了正确答案的关键词，反映检索质量而非生成质量。仅 LightRAG 侧按此指标评估。

### 4. 系统延迟（Latency）

端到端响应时间（从发送问题到收到完整回答）。

## 二、测试集设计

### 2.1 测试题来源

测试集覆盖两家公司的 16 道金融专业问题，均来自各自招股说明书原文。

## 三、评估结果

### 3.1 核心指标对比

| 指标 | 📚 RAG（BM25全文检索）| ⚡ LightRAG（hybrid 模式）| 差值 | 胜者 |
|------|------|------|------|------|
| **忠实度 Faithfulness** | 71.91% | **90.47%** | +18.56pt | LightRAG ↑↑ |
| **相关性 Answer Relevancy** | 91.05% | **92.62%** | +1.57pt | LightRAG ↑ |
| **正确率 Answer Correctness** | 66.03% | **67.22%** | +1.19pt | LightRAG ↑ |
| **关键词通过率** | 93.75% (15/16) | 93.75% (15/16) | 持平 | 持平 |
| **检索证据覆盖率** | -- | 87.00% | -- | -- |
| **平均延迟** | 7,110 ms | **295 ms** | -6815ms | LightRAG ↑↑ |
| **最大延迟** | ~14,000 ms | 2,174 ms | -11826ms | LightRAG ↑↑ |

### 3.2 RAGAS 指标详解

#### Faithfulness（忠实度）差异最显著

- **RAG 71.91%**：约 28% 的回答声明无法从检索文本中直接找到支持，LLM 有填补性发挥
- **LightRAG 90.47%**：知识图谱检索的上下文更精准，LLM 幻觉大幅减少

**原因分析：**
- RAG 的 BM25 检索返回分散 chunk，LLM 倾向用自有知识补全空白
- LightRAG 的图谱上下文包含实体描述+关系描述+原文三层信息，LLM 有充足的文本依据

#### Answer Relevancy（相关性）两者接近

- RAG 91.05% vs LightRAG 92.62%，差距仅 1.57pt
- 两套系统都能很好地抓住问题意图，DeepSeek 模型本身相关性强

#### Answer Correctness（正确率）均偏低

- RAG 66.03%，LightRAG 67.22%，两者均未超过 70%
- 原因：部分问题答案包含精确数字（如"31.28%""8,400万元"），RAGAS answer_correctness 对数字精确度要求高

### 3.3 延迟分析

| 阶段 | RAG | LightRAG |
|------|-----|---------|
| 检索阶段 | 152.5 ms | ~80 ms（图谱缓存热加载）|
| LLM 生成 | 6,957 ms | 215 ms（含缓存命中）|
| 端到端均值 | 7,110 ms | **295 ms** |
| 端到端 P95 | 13,959 ms | ~2,174 ms |

**LightRAG 速度优势来源：**
1. LLM 回答缓存（`kv_store_llm_response_cache.json`）：相同或相似问题直接返回缓存结果
2. 图谱检索比 BM25 + 向量召回+RRF 链路更短
3. 生成 prompt 更精简（实体+关系描述比大段原文 chunk 更紧凑）

> **注：** 首次（冷启动）延迟约 2-12 秒；有缓存后降至 200-300ms

## 五、评估方法

### 5.1 RAGAS 评分流程

```
收集16题的 question / answer / ground_truth / retrieved_contexts
    │
    ▼
调用 DeepSeek 作为评判 LLM（temperature=0, n=1）
调用 BGE-M3 作为评判 Embedding
    │
    ▼
RAGAS evaluate(dataset, metrics=[faithfulness, answer_relevancy, answer_correctness])
    │
    ▼
to_pandas() 提取每题分数，过滤 NaN，计算列均值
    │
    ▼
写入 summary.ragas 字段保存至 JSON
```

### 5.2 重要注意事项

1. **n=1 限制**：DeepSeek API 不支持 `n>1`，`answer_relevancy.strictness` 必须设为 1，否则报 `Invalid n value`
2. **NaN 过滤**：部分题目因上下文太长导致 RAGAS 评分超时返回 NaN，代码自动跳过 NaN 值
3. **缓存影响**：LightRAG 评估时答案均来自 LLM 缓存，与首次建图时的答案完全一致

### 5.3 评估脚本

| 脚本 | 命令 | 输出 |
|------|------|------|
| LightRAG 评估 | `python eval_lightrag.py --modes hybrid --ragas` | `output/lightrag_eval_hybrid_{ts}.json` |
| RAG 基线评估 | `python eval_quick.py --ragas` | `output/eval_results.json` |

## 六、评估结论

### 核心结论

1. **Faithfulness 差距最大（+18.56pt）**：LightRAG 的知识图谱检索有效抑制了 LLM 幻觉，回答更贴近文档原文。这是知识图谱方案相对于 chunk 检索方案最核心的优势。

2. **通过率持平（93.75%）**：两套系统关键词命中率相同，说明 LightRAG 的准确性与 RAG 相当，但忠实度更高意味着 LightRAG 是"更可靠地对的"。

3. **延迟优势显著（快 24×）**：LightRAG 有 LLM 缓存机制，重复/相似查询几乎零延迟。在实际使用中，知识库变化较少时体验远优于 RAG。

4. **Answer Correctness 均偏低**：两套系统均约 66-67%，瓶颈在于精确数字的覆盖，与检索方式无关，需要改进 ground_truth 设计或数字提取后处理。

### 适用场景建议

| 场景 | 推荐方案 |
|------|---------|
| 需要高可信度、可溯源的回答 | **LightRAG** |
| 实体关联、多跳关系查询 | **LightRAG** |
| 知识库频繁更新（不适合缓存） | RAG |
| 纯文本检索、无需图谱结构 | RAG |
| 首次冷启动延迟敏感场景 | RAG |
