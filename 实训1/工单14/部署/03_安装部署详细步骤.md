# 工单14 安装部署详细步骤 —— RAGFlow 低质量工业 PDF 图文问答系统

> 目标：从零部署 RAGFlow，建库、上传 `CN100342976C.pdf`、调到 6 问 100% 精度、响应 <3s。
> 环境：Windows 11 + Docker Desktop（本机 Docker 内存 ~12.5G）。
> 基础项目：RAGFlow v0.26.0（完整版，含内置 embedding/rerank 支持）。
> 日期：2026/06/16。

---

## 0. 前置条件

| 项 | 要求 |
|---|---|
| Docker Desktop | 已安装并运行；内存 ≥ 8G（本工单 `MEM_LIMIT=4G`） |
| 磁盘 | ≥ 15G（ragflow:v0.26.0 镜像约 9G） |
| 网络 | 能拉镜像（国内建议配代理 / registry-mirror，见附录） |
| 模型 | SiliconFlow 账号 + API Key（LLM/Embedding/VLM/Rerank） |
| `vm.max_map_count` | ≥ 262144（ES 要求；Docker Desktop 通常已满足，本机为 1048576） |

## 1. 获取源码

```bash
git clone https://github.com/infiniflow/ragflow.git
cd ragflow/docker
```

> 本工单源码位于 `E:/rag后续工单/ragflow`。

---

## 2. 配置 `.env`（关键改动）

编辑 `ragflow/docker/.env`：

```ini
# 镜像：完整版（含内置 embedding/rerank），不是 slim
RAGFLOW_IMAGE=infiniflow/ragflow:v0.26.0

# CPU 部署
DEVICE=cpu

# 内存上限：本机 Docker 仅 ~12.5G，ES 默认吃 8G 会挤爆其它容器，降到 4G
MEM_LIMIT=4G

# MySQL 宿主端口：宿主 3306 已被原生 mysqld 占用，改 5455
EXPOSE_MYSQL_PORT=5455

# 检索引擎：用 Elasticsearch
DOC_ENGINE=es
```

> ⚠️ 端口冲突排查：若机器上另有 Milvus 栈（milvus-minio/etcd/standalone 等），RAGFlow 的 minio(9000/9001)、mysql 可能撞端口。起服务前先 `docker ps` 检查，必要时停掉冲突容器或在 `.env` 改端口。

## 3. 启动服务

```bash
cd E:/rag后续工单/ragflow/docker
docker compose -f docker-compose.yml up -d
```

等待镜像拉取 + 容器启动（首次拉 ragflow:v0.26.0 约 9G，较慢）。验证 5 容器全部 healthy：

```bash
docker ps --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}"
```

期望输出（5 容器）：

| 容器 | 状态 | 端口 |
|---|---|---|
| docker-ragflow-cpu-1 | Up | 80/443、9380-9384 |
| docker-mysql-1 | Up (healthy) | 5455→3306 |

## 4. 浏览器初始化 + 配置模型

1. 打开 `http://localhost`（80 端口），注册并登录。
2. 进入 **设置 → 模型提供商**，添加 **SiliconFlow**，填入 API Key，配置：

| 角色 | 模型 |
|---|---|
| Chat（LLM） | `deepseek-v4-flash` |
| Embedding | `BAAI/bge-large-zh-v1.5` |
| Img2txt（VLM） | `Qwen/Qwen3-VL-32B-Instruct` |
| Rerank | `Qwen/Qwen3-Reranker-4B`（建库时配，最终关闭，见第 8 节） |

> Key 实际存于 MySQL `tenant_model_instance` 表（不是 `tenant_llm`，该表为空）。

---

## 5. 建知识库 + 上传文档

1. **新建知识库**，配置：
   - 分块方法：**General**
   - 解析器：**DeepDOC**
   - 语言：**Chinese**
   - **图像上下文窗口：2**（使图描述走 `_with_context` 提示词，把图周边文字喂给 VLM）
2. 上传 `data/CN100342976C.pdf`，点击**解析**。等待解析完成（DeepDOC 会做 OCR + 版面分析 + 图片区域 VLM 描述）。

---

## 6. 配置聊天助手（关键：`{knowledge}` 占位符）

新建聊天助手，绑定上面的知识库。**系统提示词模板末尾必须包含 `{knowledge}`**：

```
你是一个专业的问答助手。请严格根据下面的知识库内容回答用户问题，
不要编造知识库以外的信息。

知识库内容：
{knowledge}
```

> ⚠️ 漏掉 `{knowledge}` → 检索结果无处注入 → 模型收到空知识库 → 所有问题答"未找到"（最常见的坑）。

设置检索参数（dialog）：`top_n=8`、`similarity_threshold=0.05`、`vector_similarity_weight=0.3`。

---

## 7. 关键图人工核验（保证图片题 100%）

低分辨率工程图，VLM 自动描述可能读反方向/顺序。对第 7 页关键附图：

1. 从 MinIO 取出该图（bucket = 知识库 id，key = img_id 去掉前缀），用肉眼核对真图。
2. 写出忠于真图、不含答案、只如实描述空间关系与流向顺序的描述（参考 `fig7_fix.json`）。
3. 写回该 chunk（RAGFlow 自动重分词 + 重算向量）：

```
PUT http://localhost:9380/api/v1/datasets/{ds}/documents/{doc}/chunks/{chunk}
Authorization: Bearer <api_token>
Content-Type: application/json

{"content": "<人工核验后的图描述>"}
```

> ⚠️ 重解析会重置 chunk（id 变）并覆盖人工修正 —— 重解析后须重贴 `fig7_fix.json`。

## 8. 性能优化：关闭 Rerank（响应 <3s 关键）

单篇小知识库下，远程 Rerank 每问白吃 1.5~4s 且零精度提升。将 dialog 的 `rerank_id` 置空：

```bash
docker exec docker-mysql-1 sh -c 'mysql -uroot -pinfini_rag_flow rag_flow \
  -e "UPDATE dialog SET rerank_id=\"\" WHERE id=\"<dialog_id>\";"'
```

> 回滚（扩到大库时恢复）：把 `rerank_id` 改回 `Qwen/Qwen3-Reranker-4B@try6-15@SILICONFLOW`。

## 9. 验证：6 问精度 + 性能

### 9.1 临时 api_token（脚本调 API 用，跑完务必删）

```bash
# 建临时 token 绑 dialog
docker exec docker-mysql-1 sh -c 'mysql -uroot -pinfini_rag_flow rag_flow \
  -e "INSERT INTO api_token (tenant_id, token, dialog_id, source) \
      VALUES (\"<tenant_id>\", \"ragflow-reparse-tmp\", \"<dialog_id>\", \"agent\");"'
```

### 9.2 跑测试脚本（Windows 须设 UTF-8）

```bash
cd E:/rag后续工单
PYTHONIOENCODING=utf-8 PYTHONUTF8=1 python perf_test.py        # 6问命中 + 整段延迟
PYTHONIOENCODING=utf-8 PYTHONUTF8=1 python perf_stream.py      # 流式首字 TTFT

```

期望结果：

- 6 问精度 **6/6**
- 流式 TTFT **6/6 <3s**（0.80~1.29s，p50≈1s）
- 高并发 1~12 路 **成功率 100%**，零失败

### 9.3 收尾：删除临时 token

```bash
docker exec docker-mysql-1 sh -c 'mysql -uroot -pinfini_rag_flow rag_flow \
  -e "DELETE FROM api_token WHERE token=\"ragflow-reparse-tmp\";"'
```

## 附录：常见问题

| 现象 | 原因 | 解法 |
|---|---|---|
| 所有问题答"未找到" | 系统提示词漏 `{knowledge}` | 模板补 `{knowledge}` 占位符 |
| curl 发中文 JSON 报 `0xb8` | Git-Bash 按 GBK 编码 | 请求体写成 UTF-8 文件 `curl --data-binary @file.json` |
| Python 打印 ✅ 报 GBK 错 | Windows 控制台默认 GBK | 前置 `PYTHONIOENCODING=utf-8 PYTHONUTF8=1` |
| 裸查 ES `match content_with_weight` 0 命中 | RAGFlow 用自定义分词器 | 用 `/api/v1/retrieval` API 或 UI 检索测试 |
| 容器退出码 137 | 内存不足（OOM） | 降 `MEM_LIMIT` / 关闭其它容器 / 加 Docker 内存 |
| 镜像拉取慢 / EOF | 国内网络 | 配代理或 Docker registry-mirror（注意有的镜像源不稳） |
| 端口冲突 | 宿主已占用 3306/9000 等 | `.env` 改端口（如 `EXPOSE_MYSQL_PORT=5455`）或停冲突容器 |
| 图片题答错（方向/顺序反） | VLM 读反低清工程图 | 改图描述提示词 + 关键图人工核验写回 chunk |
