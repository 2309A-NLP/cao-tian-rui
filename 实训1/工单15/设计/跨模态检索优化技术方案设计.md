# 跨模态检索优化技术方案设计文档

## 1. 背景与问题定义

本工单基于 RAGFlow（v0.26.0）对工业专利文档 CN100347506C（块状散料分配装置）进行跨模态检索优化。该专利包含大量图文混合内容，6 个测试问题中后 4 题依赖对"第11页图3"的理解。

### 1.1 原始 RAGFlow 检索流水线

```
用户问题
  │
  ├─ 查询理解（full_question / keyword_extraction）
  │    └─ 无视觉引用识别
  │
  ├─ 混合检索（ES全文 + 向量KNN）
  │    └─ "图3"被当普通词，图文块召回权重无差异
  │
  ├─ 排序（BM25×(1-w) + cosine×w，可选Rerank）
  │
  └─ 生成（系统提示词 + {knowledge}注入）
       └─ 无跨模态分析引导
```

### 1.2 识别的两类故障

| 故障 | 表现 | 根因 |
|---|---|---|
| 故障1：检索无关 | 问"图3编号13位置"时，召回大量权利要求文本，图3相关块排名靠后 | 查询理解层无视觉引用识别，"图3"只作普通词处理 |
| 故障2：图文割裂 | 检索到图3正文块，但LLM回答"未找到相关信息" | 系统提示词无跨模态推理引导；VLM自动图描述与正文存在冲突时LLM不敢作答 |

## 2. 优化方案设计

### 2.1 设计原则

- **最小侵入**：不改 `rag/nlp/search.py` 检索主干，仅在检索调用前/后注入
- **外部可配**：所有参数写入 `conf/crossmodal_config.json`，`enabled=false` 完全回退原版
- **可回滚**：代码改动隔离在独立模块，`dialog_service.py` 改动不超过15行

### 2.2 新增模块：`rag/prompts/crossmodal.py`

| 函数 | 作用 |
|---|---|
| `detect_figure_reference(q)` | 正则识别问题中的视觉引用（图3/第N页图/figure N） |
| `enhance_query(q)` | 命中时在查询后追加图相关检索词，提升图文块召回 |
| `system_prompt_suffix(q)` | 命中时返回跨模态分析引导文本，追加至系统提示词 |
| `get_rerank_setting()` | 读外部配置，返回重排开关和模型ID |
| `rrf_fuse(list_a, list_b)` | RRF融合两路检索结果（预留，当前未启用） |

### 2.3 改动文件清单

| 文件 | 改动内容 | 行数 |
|---|---|---|
| `rag/prompts/crossmodal.py` | 新增跨模态优化模块 | +150行 |
| `conf/crossmodal_config.json` | 新增外部配置文件 | +30行 |
| `api/db/services/dialog_service.py` | 检索前调用enhance_query；生成前追加system_prompt_suffix | +6行 |

### 2.4 查询增强流程

```
用户问题："在文件中第11页图3中，编号13的部件相对于编号12..."
        │
        ▼ detect_figure_reference()
        命中"图3"
        │
        ▼ enhance_query()
        增强查询 = 原问题 + "附图说明 图示 实施例 标号 编号 部件 图3 图 3"
        │
        ▼ retrieval(增强查询)
        "附图说明/实施例/图3"等词提升图文块TF-IDF权重
        → 图3正文块（含"保护管12里设置链条13"）排名上升
```

### 2.5 跨模态提示工程

系统提示词在原有 `{knowledge}` 注入后，对含视觉引用的问题追加六条推理规则：

1. 优先依据"附图说明"段落中对应图号的文字描述作答
2. "部件A在部件B里/之内/中" = A位于B之内
3. 按编号引线与正文对应关系推断相对位置与顺序
4. **结构关系/逻辑关系**以正文文字为准；**空间方位词**（顶部/底部）正文无明确说明时可参考图描述
5. 问"散料从A进入后经过哪个部件"时，关注A内部直接接触物料的功能性部件
6. 问"调整X需操作哪个部件"时，找到"固定/安装/紧固"X的那个部件

### 2.6 外部配置参数说明

```json
{
  "enabled": true,              // 总开关，false = 完全回退原版
  "query_understanding": {
    "enabled": true,            // 查询增强开关
    "figure_terms": [...],      // 可自定义的图相关检索词列表
    "boost_repeat": 1           // 检索词重复次数（调大=更强召回，注意噪声）
  },
  "prompt_inject": {
    "enabled": true,            // 提示词注入开关
    "suffix": "..."             // 可自定义的跨模态引导文本
  },
  "fusion": {
    "rrf_enabled": false,       // RRF多路召回融合开关（预留）
    "rrf_k": 60                 // RRF平滑参数
  },
  "rerank": {
    "enabled": false,           // 重排开关
    "rerank_id": "..."          // 重排模型实例名
  }
}
```

## 3. 技术权衡说明

| 方案 | 优点 | 缺点 | 本次选择 |
|---|---|---|---|
| 改search.py检索主干 | 覆盖所有调用路径 | 风险高、难回滚 | ✗ |
| CLIP图像向量检索 | 真正的图像语义检索 | 需额外模型、ES schema变更 | ✗ |
| 查询理解+提示工程（本方案） | 最小侵入、可配、可回滚 | 依赖VLM图描述质量 | ✓ |
| 人工核验关键图描述 | 精度最高 | 不可扩展 | 辅助手段 |
