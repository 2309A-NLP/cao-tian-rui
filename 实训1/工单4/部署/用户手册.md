## 1. 系统简介

### 1.1 什么是 RAG 智能文档问答系统

RAG（Retrieval-Augmented Generation，检索增强生成）智能文档问答系统是一款基于大语言模型（LLM）与向量检索技术相结合的智能问答平台。系统允许用户上传 PDF 格式的文档资料，通过先进的文本向量化技术（BGE-M3 嵌入模型）将文档内容索引到 Milvus 向量数据库中，并结合 DeepSeek 大语言模型，实现对文档内容的精准问答。

### 1.2 核心功能

- **文档上传与解析：** 支持 PDF 格式文档的上传与自动解析，提取文本内容并按页存储。
- **向量化索引：** 使用 BGE-M3 嵌入模型将文本转化为高维向量，存储于 Milvus 向量数据库中，支持高效语义检索。
- **三种问答模式：**
  - **知识库模式（RAG）：** 从向量库中检索相关文档片段，结合 LLM 生成回答，并显示来源页码。
  - **纯 LLM 模式（Direct）：** 仅使用 LLM 自身知识库进行回答，不依赖用户上传的文档。
  - **对比模式（Both）：** 左右分栏同时展示两种模式的回答，方便用户对比分析。
- **流式输出：** 采用 SSE（Server-Sent Events）流式传输技术，回答内容实时逐字呈现，减少等待时间。
- **来源引用：** 在知识库模式下，系统会标注回答内容的文档来源及对应页码，便于溯源验证。
- **多语言界面：** 支持中文/英文界面切换。
- **历史记录：** 完整的会话与消息历史管理，支持查看和删除。
- **用户反馈：** 对比模式下支持「有帮助」/「没帮助」反馈，持续优化系统质量。

## 2. 快速开始

### 2.1 环境要求

在安装和运行系统之前，请确保您的环境满足以下要求：

| 依赖项 | 最低版本 | 推荐版本 | 说明 |
|--------|---------|---------|------|
| Python | 3.9 | 3.11 | 运行环境 |
| MySQL | 5.7 | 8.0 | 用户数据与会话存储 |
| Milvus | 2.3 | 2.4 | 向量数据库，存储文档嵌入向量 |
| pip | 最新 | 最新 | Python 包管理工具 |
| Node.js（可选） | 16 | 18+ | 仅自定义前端开发时需要 |

**硬件建议：**
- 内存：≥ 8GB（Milvus 服务启动后占用较多内存）
- 磁盘：≥ 2GB 可用空间
- 网络：需要访问 DeepSeek API（如使用在线版本）

### 2.2 安装步骤

#### 第一步：获取项目源码

项目路径为 `E:\10--agent--任务\任务 1`，请确保完整解压或克隆该目录。

#### 第二步：安装 Python 依赖

```bash
cd "E:\10--agent--任务\任务 1"
pip install -r requirements.txt
```

#### 第三步：启动 Milvus 向量数据库

Milvus 是系统的核心向量存储引擎。请根据 Milvus 官方文档完成安装：

- **Docker 方式（推荐）：**
  ```bash
  # 下载 Milvus 启动脚本
  wget https://github.com/milvus-io/milvus/releases/download/v2.4.0/milvus-standalone-docker-compose.yml -O docker-compose.yml
  # 启动服务
  sudo docker compose up -d
  ```

- **验证 Milvus 启动成功：**
  ```bash
  docker ps | grep milvus
  ```

默认 Milvus 服务地址为 `localhost:19530`。

#### 第四步：配置 MySQL 数据库

1. 确保 MySQL 服务已启动。
2. 创建数据库：
   ```sql
   CREATE DATABASE rag_doc_qa DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   ```
3. 系统启动时会自动创建所需数据表，无需手动建表。

#### 第五步：配置 DeepSeek API

在项目配置文件中设置 DeepSeek API Key：

```yaml
# config.yaml 或 .env 文件中配置
DEEPSEEK_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
DEEPSEEK_MODEL=deepseek-chat
DEEPSEEK_BASE_URL=https://api.deepseek.com
```

> **提示：** 请前往 [DeepSeek 开放平台](https://platform.deepseek.com/) 注册并获取 API Key。

### 2.3 配置说明

系统的主要配置项位于项目的配置文件中，以下是关键配置及其说明：

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `APP_HOST` | `0.0.0.0` | 服务监听地址 |
| `APP_PORT` | `8010` | 服务监听端口 |
| `MILVUS_HOST` | `localhost` | Milvus 服务地址 |
| `MILVUS_PORT` | `19530` | Milvus 服务端口 |

| `MYSQL_USER` | `root` | MySQL 用户名 |
| `MYSQL_PASSWORD` | — | MySQL 密码 |
| `MYSQL_DATABASE` | `rag_doc_qa` | MySQL 数据库名 |
| `DEEPSEEK_API_KEY` | — | DeepSeek API 密钥（必填） |
| `DEEPSEEK_MODEL` | `deepseek-chat` | 使用的模型名称 |

### 2.4 启动方式

系统提供三种启动方式，适用于不同使用场景：

#### 方式一：CLI 命令行模式

```bash
python main.py
```

适用于快速测试和单次问答场景。启动后在命令行中交互式提问。

**常用参数：**

```bash
python main.py --mode rag --query "公司的注册资本是多少？"
python main.py --mode direct --query "什么是RAG？"
python main.py --upload document.pdf
python main.py --index
python main.py --interactive
```

#### 方式二：Streamlit 前端模式（推荐）

```bash
streamlit run frontend/app.py
```

启动后浏览器自动打开 Streamlit 界面，默认地址为 `http://localhost:8501`。提供完整的图形化操作界面，包含侧边栏、聊天区、知识库管理等。

#### 方式三：FastAPI + SPA 模式

```bash
# 终端 1：启动后端 API 服务
uvicorn api.api:app --host 0.0.0.0 --port 8010

# 终端 2（可选）：用浏览器打开前端页面
# 直接在浏览器中打开 frontend/index.html
```

API 服务地址为 `http://127.0.0.1:8010`。SPA 前端通过 AJAX 请求调用后端 API，实现前后端分离架构。

> **建议：** 初次使用推荐采用 **Streamlit 模式**，操作最为直观便捷。

## 3. 用户注册与登录

### 3.1 注册新账号

首次使用系统需要先注册账号。系统支持通过 Web 界面或 API 接口进行注册。

**通过 Streamlit 界面注册：**

1. 打开 Streamlit 界面（默认 `http://localhost:8501`）。
2. 点击侧边栏或主界面中的「注册」选项。
3. 输入用户名（3-20 个字符，支持中文、英文、数字）。
4. 输入密码（建议 6 位以上，包含字母和数字）。
5. 确认密码。
6. 点击「注册」按钮。
7. 注册成功后系统会自动跳转到登录页面，或提示注册成功。

**通过 API 注册：**

```bash
curl -X POST http://127.0.0.1:8010/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"username": "zhangsan", "password": "your_password"}'
```

成功响应示例：

```json
{"code": 200, "message": "注册成功", "data": {"user_id": 1}}
```

### 3.2 登录系统

**通过 Streamlit 界面登录：**

1. 打开 Streamlit 界面。
2. 在登录页面输入已注册的用户名和密码。
3. 点击「登录」按钮。
4. 登录成功后进入主操作界面。

**通过 API 登录：**

```bash
curl -X POST http://127.0.0.1:8010/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username": "zhangsan", "password": "your_password"}'
```

成功响应示例：

```json
{"code": 200, "message": "登录成功", "data": {"token": "eyJhbGci...", "user_id": 1}}
```

> **注意：** API 登录返回的 `token` 需要在后续请求中通过 `Authorization: Bearer <token>` 头部携带，用于身份验证。

### 3.3 账号安全建议

- 请使用强密码，避免使用过于简单的组合。
- 不要将 API Token 泄露给他人。
- 如忘记密码，请联系系统管理员通过数据库重置。
- 一个用户账号可管理多个文档和多个会话。

## 4. 上传 PDF 文档

### 4.1 上传前准备

- 支持的文件格式：**PDF**（Portable Document Format）
- 单文件大小限制：默认 **50MB**（可在配置中调整）
- 文档语言：中文、英文或其他语种均可（BGE-M3 支持多语言嵌入）
- 建议：上传文本型 PDF（可选中文字），扫描型 PDF 需先进行 OCR 处理

### 4.2 通过 Streamlit 界面上传

1. 登录系统后，在左侧侧边栏找到 **「知识库管理」** 区域。
2. 点击 **「上传文档」** 或 **「Upload Document」** 按钮。
3. 在弹出的文件选择对话框中，选择本地的 PDF 文件。
4. 可一次选择多个 PDF 文件进行批量上传。
5. 等待上传完成，系统会显示上传进度和结果提示。
6. 上传成功后，文档会出现在知识库文档列表中，但此时状态为「未索引」。

### 4.3 通过 API 上传

```bash
curl -X POST http://127.0.0.1:8010/api/knowledge/upload \
  -H "Authorization: Bearer <your_token>" \
  -F "file=@/path/to/your/document.pdf"
```

成功响应示例：

```json
{
  "code": 200,
  "message": "上传成功",
  "data": {
    "doc_id": 1,
    "filename": "document.pdf",
    "pages": 42,
    "status": "pending"
  }
}
```

### 4.4 通过 CLI 上传

```bash
python main.py --upload /path/to/your/document.pdf
```

### 4.5 上传后处理流程

文档上传后，系统会自动执行以下处理：

1. **文件校验：** 检查文件格式和大小是否符合要求。
2. **PDF 解析：** 使用 PDF 解析引擎提取每一页的文本内容。
3. **文本分块：** 将提取的文本按配置的块大小（默认 512 token）进行切分，相邻块之间有重叠部分（默认 50 token）以保持上下文连贯性。
4. **元数据存储：** 将文档信息（文件名、页数、上传时间、用户ID等）存入 MySQL 数据库。
5. **状态标记：** 文档状态标记为「已上传 / 未索引」。

> **重要：** 文档上传后必须经过「索引」步骤才能用于知识库问答。

## 5. 知识库管理

### 5.1 查看文档列表

在侧边栏的「知识库管理」区域，可以查看当前用户已上传的所有文档列表。列表中包含以下信息：

| 列名 | 说明 |
|------|------|
| 文档名称 | PDF 文件的原始文件名 |
| 页数 | 文档总页数 |
| 上传时间 | 文档上传的日期和时间 |
| 索引状态 | 已索引 / 未索引 / 索引中 / 索引失败 |
| 操作 | 索引 / 重索引 / 删除 |

**通过 API 查看文档列表：**

```bash
curl -X GET http://127.0.0.1:8010/api/knowledge \
  -H "Authorization: Bearer <your_token>"
```

响应示例：

```json
{
  "code": 200,

      "doc_id": 1,
      "filename": "招股书.pdf",
      "pages": 256,
      "status": "indexed",
      "upload_time": "2026-06-05 14:30:00",

      "upload_time": "2026-06-05 15:00:00",
```

### 5.2 索引文档

索引是将上传的 PDF 文档内容转化为向量并存储到 Milvus 数据库的过程。只有经过索引的文档才能在知识库问答模式中被检索到。

**索引步骤：**

1. 在文档列表中找到需要索引的文档。
2. 点击该文档右侧的 **「索引」** 按钮。
3. 系统开始索引处理，状态变为「索引中」。
4. 索引过程中会依次执行：文本分块 → BGE-M3 向量化 → 写入 Milvus。
5. 索引完成后，状态更新为「已索引」。

**通过 API 索引：**

```bash
curl -X POST http://127.0.0.1:8010/api/knowledge/index \
  -H "Authorization: Bearer <your_token>" \
  -H "Content-Type: application/json" \
  -d '{"doc_id": 1}'
```

**通过 CLI 索引：**

```bash
python main.py --index --doc-id 1
```

> **提示：** 索引耗时取决于文档大小。100 页的 PDF 通常需要 1-3 分钟。索引期间可以继续使用系统其他功能。

### 5.3 重新索引

当文档内容更新、系统嵌入模型升级或索引出现问题时，可以对已索引的文档进行重新索引。

**重新索引步骤：**

1. 在文档列表中找到需要重新索引的文档。
2. 点击 **「重索引」** 按钮。
3. 系统会先删除该文档在 Milvus 中的旧向量数据，然后重新执行索引流程。

**通过 API 重新索引（全量）：**

```bash
curl -X GET http://127.0.0.1:8010/api/knowledge/reindex \
  -H "Authorization: Bearer <your_token>"
```

> **注意：** 重新索引会覆盖该文档之前的向量数据。全量重索引将对所有已上传文档重新建索引，耗时较长，请耐心等待。

### 5.4 删除文档

在文档列表中点击 **「删除」** 按钮，可将文档从系统中移除。删除操作会同时清除：

- 服务器上存储的 PDF 原始文件
- MySQL 数据库中的文档记录和元数据
- Milvus 中该文档对应的向量数据

> **警告：** 删除操作不可恢复，请谨慎操作。建议在删除前确认文档不再需要。

## 6. 智能问答

智能问答是系统的核心功能。用户可以针对已索引的知识库文档进行提问，也可以直接向 LLM 提问。

### 6.1 选择问答模式

在侧边栏或聊天区上方，可以通过下拉菜单或模式切换按钮选择问答模式：

| 模式 | 标识 | 说明 |
|------|------|------|
| **知识库模式** | `rag` | 从 Milvus 向量库中检索相关文档片段，结合 LLM 生成回答。回答附带来源页码引用。 |
| **纯 LLM 模式** | `direct` | 仅使用 DeepSeek 大语言模型的自身知识进行回答，不检索用户上传的文档。 |
| **对比模式** | `both` | 同时以知识库模式和纯 LLM 模式回答，左右分栏展示，便于对比分析。 |

### 6.2 知识库模式（RAG）详解

**适用场景：**
- 针对上传文档内容提问，如「公司的注册资本是多少？」
- 需要精确引用文档来源的场景
- 企业招股书、年报、技术手册等结构化文档的查询

**工作流程：**

```
用户提问 → BGE-M3 文本向量化 → Milvus 语义检索(Top-K) → 取回相关文本片段 → 构造 Prompt → DeepSeek LLM 生成回答 → 返回结果 + 来源引用
```

**使用步骤：**

1. 确保目标文档已索引完成（状态为「已索引」）。
2. 将模式切换为 **「知识库模式 / RAG」**。
3. 在聊天输入框中输入问题。
4. 点击「发送」或按 `Enter` 键。
5. 系统检索知识库并生成回答。
6. 回答下方显示来源引用标签，格式为 `📄 来源: 文档名 - 第 X 页`。

**示例问题：**
- 「公司的注册资本是多少？」
- 「募集资金的用途有哪些？」
- 「公司的主要股东是谁？」

> **提示：** 界面中提供了一键示例问题按钮（注册资本 / 募集资金 / 主要股东），点击即可快速体验。

### 6.3 纯 LLM 模式（Direct）详解

**适用场景：**
- 通用知识问答，不涉及特定文档内容
- 快速获取一般性知识或解释
- 与知识库模式进行对比验证

**使用步骤：**

1. 将模式切换为 **「纯 LLM 模式 / Direct」**。
2. 在聊天输入框中输入问题。
3. 等待 LLM 生成回答。

**特点：**
- 不依赖任何已上传文档
- 回答基于 DeepSeek 模型的预训练知识
- 无来源引用信息
- 响应速度通常比 RAG 模式稍快（省去检索步骤）

### 6.4 流式输出

系统支持 SSE（Server-Sent Events）流式输出，在两种前端界面中均有体现：

**Streamlit 前端：**
- 回答内容会以打字机效果逐字呈现
- 生成过程中聊天区底部显示「思考中...」趣味提示
- 完整回答生成后显示总耗时统计

**SPA 前端：**
- 同样支持流式文字呈现
- 使用 `EventSource` API 接收服务器推送的流式数据
- 支持中途停止生成

**API 流式接口：**

```bash
curl -X POST http://127.0.0.1:8010/api/ask/stream \
  -H "Authorization: Bearer <your_token>" \
  -H "Content-Type: application/json" \
  -d '{"query": "公司的注册资本是多少？", "mode": "rag"}' \
  --no-buffer
```

> **说明：** 流式输出使用 `Content-Type: text/event-stream`，每个事件包含一小段文本，客户端逐步拼接展示。

### 6.5 来源引用

在知识库模式下，回答内容会附带来源引用信息：

- **来源标签：** 每条回答底部会展示引用来源，格式为文档名和页码
- **可信度参考：** 来源标签帮助用户验证回答的准确性
- **多来源：** 一个回答可能引用多个文档的不同页面
- **相似度评分：** 部分场景下会展示检索片段与问题的相似度分数

来源引用示例：

```
回答：根据招股说明书，该公司的注册资本为人民币 5,000 万元。

📄 来源:
  [1] 招股说明书.pdf - 第 15 页 (相似度: 0.92)
  [2] 招股说明书.pdf - 第 23 页 (相似度: 0.87)
```

## 7. 对比模式与反馈

### 7.1 对比模式概述

对比模式（Both）是系统的一大特色功能，允许用户同时查看知识库模式和纯 LLM 模式的回答，方便进行差异分析和质量评估。

### 7.2 使用方法

1. 在模式选择中切换为 **「对比模式 / Both」**。
2. 在输入框中输入问题并发送。
3. 系统会**同时**以两种模式处理问题。
4. 界面变为**左右分栏**布局：
   - **左侧：** 知识库模式（RAG）的回答，带有来源引用
   - **右侧：** 纯 LLM 模式（Direct）的回答，无来源引用
5. 两个回答独立生成，可能存在先后差异（流式输出）。

### 7.3 对比模式界面布局

```
┌────────────────────────────────────────────────────┐
│                    用户提问                          │

│                        │                           │
│ 根据招股说明书，公司的    │ 公司的主要股东通常包括      │

│ 1. 张三，持股 35%...    │ 1. 创始人及管理团队...      │

│                        │                           │

└────────────────────────┴───────────────────────────┘
```

### 7.4 反馈功能

对比模式下，每个回答底部都配有反馈按钮：

- **👍 有帮助：** 表示该回答准确、有用
- **👎 没帮助：** 表示该回答不准确、不相关或不完整

反馈数据会被系统记录，用于：
- 评估不同问答模式的回答质量
- 后续优化 RAG 检索策略和 LLM 提示词
- 帮助开发者了解用户需求和痛点

> **提示：** 每条回答只能提交一次反馈，提交后按钮变为已选中状态，不可修改。

## 10. 常见问题 FAQ

### Q1: 上传 PDF 后为什么无法提问？

**原因：** 文档上传后需要手动执行「索引」操作。未索引的文档不会被写入向量数据库，因此 RAG 模式无法检索到相关内容。

**解决方法：** 在文档列表中找到该文档，点击「索引」按钮。等待索引完成（状态变为「已索引」）后再进行提问。

---

### Q2: 索引过程中出现错误怎么办？

**可能原因：**
- Milvus 服务未启动或连接异常
- 文档格式损坏或为扫描型 PDF（无法提取文本）
- 嵌入模型加载失败

**解决方法：**
1. 检查 Milvus 服务状态：`docker ps | grep milvus`
2. 确认文档为可选中文字的文本型 PDF
3. 查看系统日志获取详细错误信息
4. 尝试「重索引」操作

---

### Q3: RAG 模式回答不准确或不相关怎么办？

**可能原因：**
- 文档内容与问题关联性较弱
- Top-K 值过小，未检索到最相关的片段
- 文本分块过大或过小

**解决方法：**
1. 尝试调整 `TOP_K` 配置（如从 5 增大到 10）
2. 优化提问方式，使用文档中出现的关键词
3. 使用「对比模式」验证 LLM 直接回答是否更准确
4. 对文档进行重新索引

---

### Q4: 流式输出卡顿或中断怎么办？

**可能原因：**
- 网络连接不稳定（影响 DeepSeek API 调用）
- API 配额用尽或触发限流
- 服务器负载过高

**解决方法：**
1. 检查网络连接是否正常
2. 确认 DeepSeek API Key 额度充足
3. 刷新页面重试
4. 如问题持续，查看终端日志中的错误信息

---

### Q5: 系统支持哪些文件格式？

**当前支持：** PDF 格式（`.pdf`）

**不支持：** Word（`.docx`）、Excel（`.xlsx`）、TXT（`.txt`）、图片（`.jpg`/`.png`）等。

如需处理其他格式，建议先转换为 PDF 后再上传。扫描型 PDF 需先进行 OCR 处理提取文字。

---

### Q6: 如何更换 DeepSeek API Key？

在项目配置文件（`config.yaml` 或 `.env`）中修改 `DEEPSEEK_API_KEY` 字段，保存后重启服务即可生效。

---

### Q7: Milvus 连接失败如何排查？

```bash
# 检查 Milvus 容器是否运行
docker ps | grep milvus

# 检查端口是否监听
netstat -tlnp | grep 19530

# 检查网络连通性
curl http://localhost:19530/healthz

# 查看 Milvus 日志
docker logs milvus-standalone
```

如 Milvus 未运行，使用 `docker compose up -d` 重新启动。

---

### Q8: 多用户可以同时使用吗？

**可以。** 系统支持多用户注册和登录，每个用户拥有独立的：
- 文档空间（上传的文档互相隔离）
- 问答会话记录
- 知识库索引数据

用户之间的文档和对话互不影响。

---

### Q9: 对比模式的反馈数据存储在哪里？

反馈数据存储在 MySQL 数据库的反馈记录表中，包含：
- 用户 ID
- 会话 ID / 消息 ID
- 反馈类型（有帮助 / 没帮助）
- 问答模式
- 反馈时间

系统管理员可以通过数据库查询查看所有反馈数据，用于分析和优化。

---

### Q10: 如何在生产环境部署？

生产环境部署建议：

1. **使用 HTTPS：** 配置 Nginx 反向代理并启用 SSL 证书。
2. **数据库加固：** 修改 MySQL 默认密码，限制访问 IP。
3. **Milvus 集群模式：** 使用 Milvus 分布式部署提升性能和可用性。
4. **环境变量管理：** 使用 `.env` 文件管理敏感配置，不要提交到代码仓库。
5. **日志管理：** 配置日志文件输出和轮转。
6. **进程管理：** 使用 `systemd`、`supervisor` 或 `pm2` 管理服务进程。
7. **资源监控：** 监控内存、CPU 和磁盘使用情况。

```bash
# 示例：使用 uvicorn 的多 worker 模式
uvicorn api.api:app --host 0.0.0.0 --port 8010 --workers 4

# 示例：Nginx 反向代理配置
# server {
#     listen 443 ssl;
#     server_name your-domain.com;
#     location / {
#         proxy_pass http://127.0.0.1:8010;
#     }
# }
```

## 11. 界面功能说明

### 11.1 Streamlit 前端界面

侧边栏位于页面左侧，可通过左上角的 `>` 按钮展开或收起。侧边栏包含以下区域：

**🌍 语言选择**

- 切换后界面文本即时更新

**⚙️ 模式切换**
- 三个选项按钮或下拉菜单
- 可选：知识库模式 / 纯 LLM 模式 / 对比模式

- 删除按钮：删除不需要的文档
- 状态指示器：用不同颜色标识文档状态
  - 🟢 已索引（绿色）
  - 🟡 未索引（黄色）
  - 🔵 索引中（蓝色，带进度指示）
  - 🔴 索引失败（红色）

**💬 历史会话**
- 会话列表：按时间倒序显示历史会话

**➕ 新建对话**

#### 11.1.2 聊天区

聊天区占据页面主要区域，是进行问答交互的核心区域。

**来源标签**
- 仅在知识库模式下显示
- 位于 AI 回答下方
- 格式：`📄 来源: 文档名.pdf - 第 X 页`
- 多个来源分行显示

**耗时统计**
- 每条 AI 回答底部显示生成耗时
- 格式：`⏱️ 耗时: X.XXs`
- 包含检索时间 + LLM 生成时间

**思考中趣味提示**
- AI 生成回答过程中，输入框上方显示趣味提示
- 如：「正在翻阅文档，请稍候...」「AI 正在思考中 💭」「让知识库飞一会儿... 🚀」
- 目的是缓解用户等待焦虑

**输入框**
- 位于聊天区底部
- 支持多行输入（`Shift + Enter` 换行，`Enter` 发送）
- 发送按钮（`▶`）位于输入框右侧

**示例问题按钮**
- 位于聊天区底部或顶部
- 三个快捷按钮：
  - 「注册资本」→ 自动发送「公司的注册资本是多少？」
  - 「募集资金」→ 自动发送「募集资金的用途有哪些？」
  - 「主要股东」→ 自动发送「公司的主要股东是谁？」
- 点击后直接发送问题并触发回答

- 主区域分为**左右两栏**

- 每栏底部各自显示反馈按钮

#### 11.1.4 状态栏

页面顶部或底部的状态栏显示：

- **连接状态：** API 服务是否在线（🟢 在线 / 🔴 离线）

- **知识库状态：** 已索引文档数 / 已上传文档数

### 11.2 SPA 前端界面

SPA（Single Page Application）前端为纯静态 HTML 文件，通过 JavaScript 调用 FastAPI 后端接口。适合定制化开发和嵌入到其他系统中。

**主要功能与 Streamlit 前端一致，差异包括：**

- 使用原生 HTML/CSS/JS 或前端框架构建
- 通过 `fetch` 或 `XMLHttpRequest` 调用 RESTful API
- 流式输出通过 `EventSource` 接收 SSE 数据
- 界面定制化程度更高
- 不依赖 Python 运行时（纯前端）

**打开方式：**

```bash
# 直接在浏览器中打开
start frontend/index.html

# 或使用简易 HTTP 服务器
cd frontend && python -m http.server 8080
# 访问 http://localhost:8080
```

> **注意：** SPA 前端需要 FastAPI 后端服务运行在 `http://127.0.0.1:8010`，请确保后端已启动。
