## 4. 核心模块设计

### 4.1 pdf_processor — PDF 处理模块

**文件**: `backend/pdf_processor.py`

#### 功能概述

负责 PDF 文档的解析、表格检测、自然语言转换和文本分块，是知识库构建的核心入口。

#### 表格检测机制

| 步骤 | 处理内容 | 技术方案 | 输出 |
|------|---------|---------|------|
| 1. 页面解析 | 逐页提取文本与结构 | PyPDF2 / pdfplumber | 页面元素列表 |
| 2. 表格识别 | 检测页面中的表格区域 | pdfplumber.table_detection | 表格边界坐标 |
| 3. 单元格提取 | 提取表格行列数据 | 坐标映射 + 文本合并 | 二维数组 |
| 4. 结构校验 | 去除空行、合并单元格处理 | 启发式规则 | 清洗后表格 |
| 5. NL转换 | 表格数据转自然语言描述 | 模板生成 + LLM改写 | 可检索文本 |

#### 表格自然语言转换示例

```
原始表格:
| 产品   | 单价  | 销量  |
|--------|------|------|
| 产品A  | 100  | 500  |
| 产品B  | 200  | 300  |

转换后自然语言:
"产品A的单价为100元，销量为500件；产品B的单价为200元，销量为300件。
其中产品A销量更高（500件），产品B单价更高（200元）。"
```

#### 文本分块策略

| 参数 | 默认值 | 说明 |
|------|--------|------|
| chunk_size | 512 | 单块最大token数 |
| chunk_overlap | 64 | 块间重叠token数 |
| min_chunk_size | 50 | 最小块大小，过小则合并 |
| separator | \n\n | 优先分割符 |

分块优先级：段落分隔 > 句号分隔 > 换行分隔 > 强制截断

#### 处理流程

```
PDF文件上传
    │
    ▼
┌───────────────┐
│ 读取PDF页面    │
└───────┬───────┘
        ▼
┌───────────────┐     ┌──────────────┐
│ 检测表格区域   │────→│ 表格NL转换    │
└───────┬───────┘     └──────┬───────┘
        ▼                    │
┌───────────────┐            │
│ 提取纯文本     │◄───────────┘
└───────┬───────┘
        ▼
┌───────────────┐
│ 文本分块       │
└───────┬───────┘
        ▼
┌───────────────┐
│ 生成向量嵌入   │ (BGE-M3)
└───────┬───────┘
        ▼
┌───────────────┐
│ 存入Milvus    │ + BM25索引
└───────────────┘
```

### 4.2 retrieval_strategy — 检索策略模块

**文件**: `backend/retrieval_strategy.py`

#### 功能概述

实现多层次智能检索策略，包括混合检索、RRF 融合、查询改写、关键词重排、自适应重排和强制召回机制。

#### 混合检索架构

```
用户查询
    │
    ├──────────────────────────────┐
    ▼                              ▼
┌──────────────┐           ┌──────────────┐
│  向量检索     │           │  BM25检索     │
│  (语义匹配)   │           │  (关键词匹配)  │
│  BGE-M3编码   │           │  TF-IDF      │
│  Top-K=20    │           │  Top-K=20    │
└──────┬───────┘           └──────┬───────┘
       │                          │
       └──────────┬───────────────┘
                  ▼
          ┌──────────────┐
          │  RRF 融合排序  │
          │  Reciprocal   │
          │  Rank Fusion  │
          └──────┬───────┘
                 ▼
          ┌──────────────┐
          │  重排序策略    │
          └──────┬───────┘
                 ▼
          ┌──────────────┐
          │  强制召回检查  │
          └──────┬───────┘
                 ▼
          最终结果集 (Top-K)
```

#### RRF 融合算法

RRF (Reciprocal Rank Fusion) 公式：

```
RRF_score(d) = Σ 1 / (k + rank_i(d))

其中：
- k = 60 (常数，避免分母为零)
- rank_i(d) = 文档d在第i个检索器中的排名
- 对向量检索和BM25检索的结果取并集后计算
```

| 参数 | 默认值 | 说明 |
|------|--------|------|
| rrf_k | 60 | RRF常数参数 |
| vector_top_k | 20 | 向量检索返回数量 |
| bm25_top_k | 20 | BM25检索返回数量 |
| final_top_k | 10 | 融合后最终返回数量 |

#### 查询改写策略

| 改写类型 | 触发条件 | 处理方式 | 示例 |
|---------|---------|---------|------|
| 同义词扩展 | 查询词过短 | LLM生成同义词变体 | "价格" → "价格 费用 成本 报价" |
| 意图补全 | 查询模糊 | 补充上下文意图 | "怎么做" → "这个产品的使用方法是什么" |
| 多查询生成 | 复杂问题 | 生成多个子查询 | 分解为2-3个子问题并行检索 |
| 历史上下文 | 多轮对话 | 结合历史消息改写 | 代词消解，指代明确化 |

#### 关键词重排

| 步骤 | 说明 |
|------|------|
| 1. 关键词提取 | 从查询中提取核心关键词（jieba分词 + TF-IDF） |
| 2. 匹配度计算 | 计算每个结果片段中关键词命中比例 |
| 3. 加权调整 | 在RRF得分基础上叠加关键词匹配权重 |
| 4. 归一化 | 将综合得分归一化到 [0, 1] |

#### 自适应重排

根据查询特征自动选择最佳排序策略：

| 查询特征 | 判定条件 | 重排策略 |
|---------|---------|---------|
| 事实型问题 | 包含"是什么""多少"等 | 偏向精确匹配，提高关键词权重 |
| 分析型问题 | 包含"分析""对比""原因" | 偏向语义相关，提高向量权重 |
| 列表型问题 | 包含"有哪些""列出" | 偏向覆盖度，提高多样性得分 |
| 时间敏感问题 | 包含日期、"最新"等 | 偏向新鲜度，提高时间因子 |

#### 强制召回机制

当检索结果质量不足时，触发强制召回确保关键文档不遗漏：

| 条件 | 阈值 | 处理动作 |
|------|------|---------|
| 结果数量不足 | < min_recall_count (默认3) | 扩大检索范围，降低相似度阈值 |
| 最高得分过低 | < score_threshold (默认0.3) | 启用宽松匹配模式 |
| 关键文档命中 | 公司核心文档未命中 | 强制插入相关核心文档 |
| 零结果 | 返回0条结果 | 切换为纯BM25关键词检索 |

### 4.3 vector_store — 向量存储模块

**文件**: `backend/vector_store.py`

#### 功能概述

管理 Milvus 向量数据库和 BM25 全文检索索引，提供统一的存储与检索接口。

#### Milvus 集合管理

| 操作 | 方法 | 说明 |
|------|------|------|
| 创建集合 | create_collection() | 创建带 schema 的 Milvus 集合 |
| 插入向量 | insert() | 批量插入 chunk 数据及向量 |
| 向量检索 | search() | 基于向量相似度的 ANN 检索 |
| 删除集合 | drop_collection() | 删除指定集合 |
| 集合列表 | list_collections() | 列出所有文档集合 |

#### BM25 全文检索

| 特性 | 实现方案 |
|------|---------|
| 索引构建 | 对文本分词后构建倒排索引 |
| 分词器 | jieba 中文分词 |
| 评分算法 | BM25 (k1=1.5, b=0.75) |
| 存储方式 | 内存索引 + 持久化到磁盘 |

#### 双路检索流程

```
查询输入
    │
    ├──→ BGE-M3编码 ──→ Milvus向量检索 (ANN, Top-K)
    │                          │
    │                          ▼
    │                    向量结果集 + 分数
    │
    └──→ jieba分词 ──→ BM25检索 (Top-K)
                              │
                              ▼
                        BM25结果集 + 分数
                              │
                    ┌─────────┴─────────┐
                    ▼                   ▼
              RRF融合排序          返回给 retrieval_strategy
```

### 4.4 rag_engine — RAG 引擎模块

**文件**: `backend/rag_engine.py`

#### 功能概述

RAG 系统的核心引擎，整合检索与生成，支持流式回答和对比模式。

#### 流式回答机制

| 阶段 | 处理内容 | 输出格式 |
|------|---------|---------|
| 1. 检索阶段 | 调用 retrieval_strategy 获取相关文档 | SSE: event=metadata |
| 2. 上下文构建 | 将检索结果格式化为 prompt | 内部处理 |
| 3. 流式生成 | DeepSeek API 流式返回 | SSE: event=message, data=token |
| 4. 来源标注 | 附加引用来源信息 | SSE: event=sources |
| 5. 完成标记 | 标记回答完成 | SSE: event=done |

SSE 数据格式：
```
event: metadata
data: {"retrieved_docs": 5, "query_rewrite": "改写后的查询"}

event: message
data: {"token": "根据"}

event: message
data: {"token": "文档"}

event: sources
data: {"sources": [{"page": 3, "doc": "产品手册.pdf", "score": 0.85}]}

event: done
data: {"status": "complete", "total_tokens": 512}
```

#### 对比模式

对比模式同时运行两套 RAG 策略，让用户直观比较不同配置的回答质量：

| 对比维度 | 策略 A (默认) | 策略 B (对照) |
|---------|-------------|-------------|
| 检索方式 | 混合检索 (向量+BM25) | 纯向量检索 |
| 重排序 | 启用多级重排 | 无重排 |
| 查询改写 | 启用 | 禁用 |
| 强制召回 | 启用 | 禁用 |

对比模式流程：
```
用户提问
    │
    ├──→ 策略A (完整pipeline) ──→ 回答A + 来源A
    │
    └──→ 策略B (简化pipeline) ──→ 回答B + 来源B
                                      │
                                      ▼
                              并排展示 + 反馈按钮
                              (👍/👎 评价每个回答)
```

#### Prompt 模板设计

```
系统提示词模板：
"""
你是一个专业的企业知识问答助手。请根据以下参考文档回答用户问题。

规则：
1. 仅基于提供的文档内容回答，不要编造信息
2. 如果文档中没有相关信息，请明确告知
3. 回答中引用来源，格式：[来源: 文档名, 第X页]
4. 保持回答简洁准确

参考文档：
{context}

用户问题：{question}
"""
```

### 4.5 company_filter — 公司文档路由模块

**文件**: `backend/company_filter.py`

#### 功能概述

实现多公司、多文档的智能路由，根据用户查询自动匹配相关公司文档集，缩小检索范围。

#### 路由策略

| 匹配层级 | 匹配方式 | 示例 |
|---------|---------|------|
| L1: 精确匹配 | 查询中明确提到公司名称 | "华为的营收" → 华为文档集 |
| L2: 关键词匹配 | 查询包含公司特有术语 | "麒麟芯片" → 华为文档集 |
| L3: 语义匹配 | 查询语义与文档主题相关 | 嵌入向量相似度 > 阈值 |
| L4: 全局回退 | 无法匹配特定公司 | 检索所有文档集 |

#### 文档路由流程

```
用户查询: "华为2024年的营收是多少"
    │
    ▼
┌─────────────────┐
│ L1 公司名检测     │  → 匹配到"华为"
└───────┬─────────┘
        ▼
┌─────────────────┐
│ 过滤文档集合      │  → 仅检索华为相关PDF集合
└───────┬─────────┘
        ▼
┌─────────────────┐
│ 执行检索pipeline │  → 在限定范围内混合检索
└───────┬─────────┘
        ▼
┌─────────────────┐
│ 生成回答         │  → 引用华为文档来源
└─────────────────┘
```

#### 配置示例

```json
{
  "company_documents": {
    "华为": ["华为年报2024.pdf", "华为产品手册.pdf"],
    "腾讯": ["腾讯年报2024.pdf", "腾讯业务报告.pdf"],
    "阿里巴巴": ["阿里年报2024.pdf"]
  }
}
```

## 6. 向量存储设计

### 6.1 Milvus Collection Schema

| 字段名 | 数据类型 | 约束 | 说明 |
|--------|---------|------|------|
| chunk_id | VARCHAR(64) | PRIMARY KEY | 文本块唯一标识 (UUID) |

| vector | FLOAT_VECTOR(1024) | - | BGE-M3生成的1024维稠密向量 |

### 6.2 索引配置

| 索引类型 | 字段 | 算法 | 参数 | 说明 |
|---------|------|------|------|------|
| 向量索引 | vector | HNSW | M=16, efConstruction=256 | 高精度近似最近邻 |
| 标量索引 | chunk_id | - | - | 主键自动索引 |
| 标量索引 | field_type | - | - | 支持按类型过滤 |

### 6.3 Collection 命名规则

```
collection名称 = "doc_" + 文档ID哈希

每个上传的PDF文档对应一个独立的Milvus Collection，
支持按文档粒度的增删查操作。
```

### 6.4 向量检索参数

| 参数 | 值 | 说明 |
|------|------|------|
| metric_type | COSINE | 余弦相似度 |
| nprobe | 16 | 搜索时探针数 |
| top_k | 20 | 单路检索返回数量 |
| score_threshold | 0.3 | 最低相似度阈值 |

| 重排序 | 10-30ms | 规则引擎 |

| **端到端** | **2-6s** | 首token响应 <1s |
