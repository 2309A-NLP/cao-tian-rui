## 一、已知问题清单（P1-P10）

### P1：PyMuPDF表格解析正则缺陷 —— 逗号缺失

**严重程度：高** | **影响范围：PDF表格提取阶段**

**现象描述：**  
PyMuPDF提取表格后，正则表达式解析数字字段时遗漏逗号分隔符，导致金额、数量等数值字段被错误拼接。例如 `"1,234,567"` 被解析为 `"1234567"` 或 `"1234 567"`，下游表格结构化数据全部失真。

**根因分析：**  
```python
# 问题代码示例
import re
text = "营业收入 1,234,567.89 元"
# 原正则：r'(\d+)\.(\d+)'  缺少逗号匹配
result = re.findall(r'(\d+)[,.]?(\d+)?\.(\d+)?', text)
# 逗号被当作普通字符跳过，导致分组错位
```
正则表达式 `r'[\d.]+'` 将逗号视为非数字字符直接跳过，未考虑千位分隔符场景。

**修复方案：**  
```python
# 修复后：预处理阶段保留逗号，解析时统一处理
text_clean = re.sub(r'(\d),(\d)', r'\1\2', text)  # 去除千位逗号
# 或在正则中显式匹配逗号
pattern = r'(\d{1,3}(?:,\d{3})*(?:\.\d+)?)'
```

### P2：中文关键词重排无空格分词问题

**严重程度：高** | **影响范围：BM25检索 & keyword_rerank**

**现象描述：**  
中文文本天然无空格分词，`keyword_rerank` 模块默认按空格切词后匹配，导致中文query几乎无法命中任何关键词，重排分数趋近于0，检索结果随机排序。

**根因分析：**  
```python
# 问题代码
keywords = query.split()  # "财务报表分析" -> ["财务报表分析"] 整体作为一个token
# BM25索引中存储的是分词后的结果，两者粒度不匹配
```

**修复方案：**  
集成jieba分词，在keyword_rerank前对query和文档均做中文分词：
```python
import jieba
keywords = list(jieba.cut(query))  # ["财务", "报表", "分析"]
```

### P3：keyword_rerank 三重陷阱

**严重程度：中** | **影响范围：重排模块**

**陷阱1 — boost权重失控：**  
`boost_factor` 设置过大（如10.0），关键词匹配分数完全压倒语义相似度分数，导致包含关键词但语义无关的文档被排到最前。

**陷阱2 — combined_score融合不合理：**  
`combined_score = alpha * semantic + (1-alpha) * keyword` 中alpha=0.5时，两路分数量纲差异大（语义0-1，关键词可能0-100），融合后关键词主导。

**陷阱3 — key_phrases提取不准：**  
基于TextRank提取关键短语时，中文停用词表缺失，"的"、"了"、"是"等高频虚词被当作关键短语。

**修复方案：**  
- boost_factor限制在1.0-2.0之间，且做归一化  
- 融合前先将两路分数归一化到[0,1]  
- 补充中文停用词表，过滤长度<2的短语

### P4：模板页/样板页检索得分异常高

**严重程度：高** | **影响范围：检索结果质量**

**现象描述：**  
招股书、年报中的目录页、免责声明页、公司介绍模板页等样板内容，因用词通用且覆盖面广，Embedding相似度和BM25得分均偏高，频繁出现在top-k结果中。

**根因分析：**  
模板页内容包含大量通用性词汇（"本公司"、"报告期内"、"董事会"等），与多数query的词频分布高度重叠，且Embedding模型未学到"模板vs实质内容"的区分。

**修复方案：**  
- 构建模板页指纹库（SimHash/MinHash），入库时过滤  
- 检索后增加模板页检测后处理，降低排名  
- 配置黑名单页码范围（如年报第1-5页常为模板）

---

### P5：rerank_top_n=20 上限过小

**严重程度：中** | **影响范围：召回率**

**现象描述：**  
当前 `rerank_top_n=20`，即从向量检索top-100中只取20条送入Reranker。当答案分布较分散（如多文档对比场景），20条不足以覆盖所有相关片段，导致答案不完整。

**根因分析：**  
配置硬编码为20，未随检索集合规模和查询复杂度动态调整。简单查询20条足够，但复杂查询需要50-100条。

**修复方案：**  
- 默认提升到50，复杂查询（检测到多实体/对比类query）提升到100  
- 增加动态调整逻辑：query长度>50字或含"对比"/"比较"关键词时提升上限

### P6：system_prompt存在幻觉诱导

**严重程度：高** | **影响范围：LLM回答质量**

**现象描述：**  
当前system_prompt包含"你是专业分析师，请给出详细分析"等指令，LLM在检索内容不足时倾向于"编造"分析内容，产生幻觉。

**根因分析：**  
Prompt中缺少"仅基于提供的上下文回答"、"不确定时明确说明"等约束性指令。

**修复方案：**  
```python
system_prompt = """
你是一个严格基于文档的问答助手。
规则：
1. 仅根据<参考资料>中的内容回答问题
2. 如果参考资料中没有相关信息，回答"根据现有资料无法回答此问题"
3. 不要推测、推断或编造任何信息
4. 引用原文时标注来源
"""
```

### P7：多文档交叉污染

**严重程度：高** | **影响范围：多文档场景**

**现象描述：**  
用户上传A公司和B公司文档后提问"A公司营收"，系统可能返回B公司的数据，因为检索阶段未区分文档来源，混合排序后将B公司高分片段排在前面。

**根因分析：**  
向量数据库中存储的chunk未携带有效company标签，或检索时未按company_filter过滤。多文档embedding混合在同一索引中，无法区分。

**修复方案：**  
- chunk入库时强制携带metadata（company_name, doc_type, upload_time）  
- 检索时根据query识别目标公司，传递company_filter参数  
- Milvus/FAISS检索时增加metadata过滤条件

### P8：BM25检索模块未就绪

**严重程度：中** | **影响范围：混合检索**

**现象描述：**  
BM25模块代码已编写但未集成到主检索流程中，当前仅使用向量检索，缺少稀疏检索通道，对精确关键词查询效果差。

**根因分析：**  
- 依赖的jieba分词词典未下载  
- BM25索引构建脚本未在入库流程中调用  
- 混合检索的融合权重未调优

**修复方案：**  
补全BM25索引构建流程，集成到入库pipeline，混合检索时使用RRF（Reciprocal Rank Fusion）融合。

### P9：图片OCR缺失

**严重程度：中** | **影响范围：图文PDF处理**

**现象描述：**  
PDF中的图片（如财务图表、架构图、流程图）中的文字信息未被提取，导致关键信息丢失。用户问"系统架构是什么"时，架构图中的内容无法被检索到。

**根因分析：**  
当前PDF解析流程仅提取文本流，未调用OCR引擎处理图片中的文字。

**修复方案：**  
- 集成PaddleOCR或Tesseract对PDF内嵌图片做OCR  
- marker-pdf本身支持OCR，可开启其OCR模式  
- OCR结果作为补充chunk入库

### P10：配置文件路径Windows/WSL不兼容

**严重程度：低** | **影响范围：跨环境部署**

**现象描述：**  
配置文件中使用 `E:\10--agent--任务` 等Windows路径格式，在WSL环境下路径解析失败，反之亦然。

**根因分析：**  
硬编码绝对路径，未做平台检测和路径转换。

**修复方案：**  
```python
import platform, os
if platform.system() == 'Windows':
    base_path = r"E:\10--agent--任务"
else:
    base_path = "/mnt/e/10--agent--任务"
```
或使用 `pathlib.Path` 统一处理。

### 优化方向1：PDF解析 —— marker-pdf混合方案

| 维度 | 内容 |
|------|------|
| **现状问题** | marker-pdf处理10页PDF耗时6209秒（~103分钟），速度不可接受；PyMuPDF速度快但表格/复杂布局解析差 |
| **解决方案** | 构建混合解析pipeline：简单页面（纯文本）用PyMuPDF（<1秒/页），复杂页面（表格/图片/多栏）用marker-pdf；引入页面复杂度预判模块（基于图片占比、表格检测） |
| **预期效果** | 解析速度提升10-50倍，复杂页面质量保持marker-pdf水平 |
| **难度** | ⭐⭐⭐ (3/5) |
| **优先级** | **P1** |

**核心代码示意：**
```python
class HybridPDFParser:
    def parse(self, pdf_path):
        pages = pymupdf.open(pdf_path)
        results = []
        for i, page in enumerate(pages):
            complexity = self._assess_complexity(page)
            if complexity < 0.3:  # 简单页面
                results.append(self._pymupdf_parse(page))
            else:  # 复杂页面
                results.append(self._marker_parse(pdf_path, i))
        return results
    
    def _assess_complexity(self, page):
        """基于图片占比、表格密度、多栏检测计算复杂度"""
        img_ratio = page.get_images() / page.rect.width * page.rect.height
        has_table = self._detect_table(page)
        is_multicolumn = self._detect_columns(page)
        return img_ratio * 0.4 + has_table * 0.4 + is_multicolumn * 0.2
```

### 优化方向2：分块策略 —— 语义分块

| 维度 | 内容 |
|------|------|
| **现状问题** | 当前使用固定长度分块（如512token），可能在句子中间截断，破坏语义完整性 |
| **解决方案** | 引入语义分块：基于段落边界、标题层级、句子相似度进行智能切分；使用LangChain的`RecursiveCharacterTextSplitter`或自定义基于句子embedding的分块器 |
| **预期效果** | 检索准确率提升15-25%，减少跨语义边界的噪声chunk |
| **难度** | ⭐⭐ (2/5) |
| **优先级** | **P1** |

**核心代码示意：**
```python
from langchain.text_splitter import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    chunk_size=512,
    chunk_overlap=64,
    separators=["\n\n", "\n", "。", "；", "，", " "],  # 中文优先分隔符
    length_function=len,
)

# 进阶：基于embedding相似度的语义分块
def semantic_chunk(text, threshold=0.75):
    sentences = split_sentences(text)
    chunks, current = [], [sentences[0]]
    for i in range(1, len(sentences)):
        sim = cosine_sim(embed(sentences[i-1]), embed(sentences[i]))
        if sim < threshold:
            chunks.append("".join(current))
            current = []
        current.append(sentences[i])
    chunks.append("".join(current))
    return chunks
```

### 优化方向3：检索质量提升 —— Query Rewrite / HyDE / 多路召回

| 维度 | 内容 |
|------|------|
| **现状问题** | 用户query口语化、简短、含歧义，直接检索效果差；单路向量召回覆盖率不足 |
| **解决方案** | ① Query Rewrite：LLM改写query为结构化检索语句；② HyDE：先让LLM生成假设性答案，用答案做检索；③ 多路召回：向量+BM25+关键词三路召回后RRF融合 |
| **预期效果** | 召回率提升30-50%，尤其改善口语化和模糊查询 |
| **难度** | ⭐⭐⭐⭐ (4/5) |
| **优先级** | **P0** |

**核心代码示意：**
```python
# Query Rewrite
def rewrite_query(original_query):
    prompt = f"""将以下用户问题改写为3个不同角度的检索query：
    原始问题：{original_query}
    要求：保持语义，使用专业术语，输出JSON数组"""
    return llm.generate(prompt)

# HyDE
def hyde_retrieve(query):
    hypothetical = llm.generate(f"请回答：{query}")  # 假设性答案
    return vector_search(hypothetical, top_k=20)

# RRF多路融合
def rrf_fusion(results_lists, k=60):
    scores = {}
    for results in results_lists:
        for rank, doc in enumerate(results):
            scores[doc.id] = scores.get(doc.id, 0) + 1/(k + rank + 1)
    return sorted(scores.items(), key=lambda x: -x[1])
```

### 优化方向4：重排模块 —— Cross-Encoder / ColBERT

| 维度 | 内容 |
|------|------|
| **现状问题** | 当前重排依赖简单关键词匹配，语义重排能力弱；Cross-Encoder模型未部署或版本过旧 |
| **解决方案** | 部署`bge-reranker-v2-m3`或`bce-reranker-base_v1`作为Cross-Encoder重排器；对候选chunk与query做交叉注意力计算相关性分数 |
| **预期效果** | 重排后top-5准确率提升20-30% |
| **难度** | ⭐⭐ (2/5) |
| **优先级** | **P1** |

**核心代码示意：**
```python
from sentence_transformers import CrossEncoder

reranker = CrossEncoder('BAAI/bge-reranker-v2-m3')

def rerank(query, candidates, top_n=10):
    pairs = [[query, doc.text] for doc in candidates]
    scores = reranker.predict(pairs)
    ranked = sorted(zip(candidates, scores), key=lambda x: -x[1])
    return [doc for doc, _ in ranked[:top_n]]
```

### 5.1 完整混合检索Pipeline

```python
class HybridRetriever:
    def __init__(self, vector_store, bm25_index, reranker):
        self.vector_store = vector_store
        self.bm25_index = bm25_index
        self.reranker = reranker
    
    def retrieve(self, query, company_filter=None, top_k=10):
        # 1. Query Rewrite
        queries = self._rewrite_query(query)
        
        # 2. 多路召回
        vector_results = []
        for q in queries:
            vector_results.extend(
                self.vector_store.search(q, filter=company_filter, top_k=30)
            )
        
        bm25_results = self.bm25_index.search(
            " ".join(jieba.cut(query)), top_k=30, filter=company_filter
        )
        
        # 3. RRF融合
        fused = self._rrf_fusion([vector_results, bm25_results])
        
        # 4. 模板页过滤
        filtered = [doc for doc in fused if not self._is_template(doc)]
        
        # 5. Cross-Encoder重排
        reranked = self.reranker.rerank(query, filtered[:50], top_n=top_k)
        
        return reranked
```
