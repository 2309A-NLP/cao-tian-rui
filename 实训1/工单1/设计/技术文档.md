# RAG 智能问答系统 — 技术文档

## 1. 项目概述

本项目基于 **检索增强生成（RAG）** 技术，构建了一套支持 PDF 文档导入、向量化存储、语义检索与大模型问答的智能问答系统。用户可上传 PDF 文档至知识库，系统自动完成文档解析、文本分块、向量嵌入与存储；提问时系统从向量库中检索相关片段作为上下文，结合大语言模型生成精准回答。

---

## 2. 系统架构

系统采用分层架构设计，共分为四层：

```
┌─────────────────────────────────────────────┐
│              frontend（前端层）               │
│        Streamlit / Vue SPA 界面              │
├─────────────────────────────────────────────┤
│               api（接口层）                   │
│         FastAPI RESTful API + SSE            │
├─────────────────────────────────────────────┤
│             backend（业务层）                 │
│   RAGEngine / PDFProcessor / LLMFactory      │
├─────────────────────────────────────────────┤
│            framework（基础层）                │
│     VectorStore(Milvus) / DatabaseManager    │
└─────────────────────────────────────────────┘
```

### 2.1 目录结构

```
任务 1/
├── backend/              # 业务逻辑
│   ├── pdf_processor.py  # PDF 解析与分块
│   ├── rag_engine.py     # RAG 检索与生成引擎
│   └── llm_factory.py    # 大模型调用工厂
├── api/                  # FastAPI 接口层
│   ├── main.py           # 应用入口 & 路由注册
│   ├── auth.py           # 认证接口
│   ├── knowledge.py      # 知识库接口
│   ├── ask.py            # 问答接口

├── frontend/             # 前端界面
│   ├── streamlit_app.py  # Streamlit 版
│   └── spa/              # Vue SPA 版
├── framework/            # 基础设施
│   ├── vector_store.py   # Milvus 向量存储

```

### 2.2 数据流

**文档入库流程：**

```
PDF 文件 → PDFProcessor(解析/分块) → BGE-M3(向量嵌入) → VectorStore → Milvus
```

**问答流程：**

```
用户提问 → BGE-M3(查询向量化) → VectorStore(语义检索) → RAGEngine(拼装上下文) → DeepSeek(生成回答) → 返回用户
```

## 4. 核心模块设计

### 4.1 PDFProcessor（PDF 处理器）

**职责：** 负责 PDF 文档的解析、文本提取与智能分块。

- 使用 PyMuPDF / pdfplumber 提取每页文本内容
- 按段落或固定长度（可配置 chunk_size）进行分块
- 保留页码、字段类型等元信息
- 输出结构化的文本块列表，供下游向量化

### 4.2 RAGEngine（RAG 引擎）

**职责：** 核心检索增强生成引擎，协调检索与生成。

- 接收用户查询，调用 BGE-M3 生成查询向量
- 通过 VectorStore 检索 Top-K 相关文本块
- 将检索结果作为上下文与用户问题拼装为 Prompt
- 调用 LLMFactory 获取大模型回答
- 支持三种查询模式：`rag`（纯检索增强）、`direct`（直连大模型）、`both`（同时返回两种结果）

### 4.3 VectorStore（向量存储）

**职责：** 封装 Milvus 向量数据库的读写操作。

- 管理 Collection 的创建、索引构建与删除
- 提供向量插入（批量入库）与向量检索（ANN 搜索）
- 支持按知识库名称隔离数据
- 使用余弦相似度（COSINE）作为距离度量

### 4.4 LLMFactory（大模型工厂）

**职责：** 统一管理大语言模型的调用。

- 封装 DeepSeek API 的 HTTP 调用
- 支持普通同步调用与 SSE 流式输出
- 统一的 Prompt 模板管理
- 错误重试与超时处理

### 4.5 DatabaseManager（数据库管理器）

**职责：** 封装 MySQL 数据库操作。

- 用户注册、登录验证（密码哈希存储）
- 聊天历史记录的增删查
- 使用连接池管理数据库连接

## 5. 数据库设计

### 5.1 MySQL 表结构

#### users 表（用户表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INT AUTO_INCREMENT PRIMARY KEY | 用户 ID |
| username | VARCHAR(50) UNIQUE NOT NULL | 用户名 |
| password_hash | VARCHAR(256) NOT NULL | 密码哈希值 |
| created_at | DATETIME DEFAULT CURRENT_TIMESTAMP | 注册时间 |

#### chat_history 表（聊天历史表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INT AUTO_INCREMENT PRIMARY KEY | 记录 ID |
| user_id | INT NOT NULL | 用户 ID（外键关联 users.id） |
| question | TEXT NOT NULL | 用户提问 |
| answer | TEXT NOT NULL | 模型回答 |
| mode | VARCHAR(20) | 查询模式（rag/direct/both） |
| knowledge_base | VARCHAR(100) | 使用的知识库名称 |
| created_at | DATETIME DEFAULT CURRENT_TIMESTAMP | 创建时间 |

### 5.2 Milvus Collection Schema

Collection 名称按知识库名称动态创建，字段定义如下：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| chunk_id | INT64 (主键) | 文本块唯一标识 |
| page | INT64 | 所在页码 |
| field_type | VARCHAR(64) | 字段类型/分类标签 |
| text | VARCHAR(65535) | 原始文本内容 |
| vector | FLOAT_VECTOR(1024) | BGE-M3 生成的 1024 维向量 |

**索引配置：**

- 索引类型：IVF_FLAT / HNSW
- 距离度量：COSINE
- nlist：128（IVF_FLAT 参数）

## 7. 配置文件设计

项目通过 `config.json` 管理所有可配置项：

```json
{
  "milvus": {
    "host": "127.0.0.1",
    "port": 19530,
    "collection_prefix": "kb_"
  },
  "mysql": {
    "host": "127.0.0.1",
    "port": 3307,
    "user": "root",
    "password": "your_password",
    "database": "rag_system"
  },
  "embedding": {
    "model": "BAAI/bge-m3",
    "dimension": 1024,
    "device": "cpu"
  },
  "llm": {
    "provider": "deepseek",
    "api_key": "your_deepseek_api_key",
    "model": "deepseek-chat",
    "base_url": "https://api.deepseek.com",
    "max_tokens": 2048,
    "temperature": 0.7
  },
  "rag": {
    "chunk_size": 512,
    "chunk_overlap": 64,
    "top_k": 5,
    "similarity_threshold": 0.5
  },
  "server": {
    "host": "0.0.0.0",
    "port": 8000,
    "debug": false
  },
  "auth": {
    "secret_key": "your_jwt_secret",
    "token_expire_hours": 24
  }
}
```

| 配置段 | 关键字段 | 说明 |
|--------|---------|------|
| milvus | host, port | Milvus 连接地址 |
| mysql | host, port, user, password, database | MySQL 连接信息 |
| embedding | model, dimension, device | 嵌入模型配置 |
| llm | provider, api_key, model, base_url | 大模型 API 配置 |
| rag | chunk_size, chunk_overlap, top_k | RAG 参数 |
| server | host, port | 服务监听地址 |
| auth | secret_key, token_expire_hours | JWT 认证配置 |

## 8. 部署方式

系统支持三种运行模式：

### 8.1 命令行模式（CLI）

```bash
python main.py --mode cli
```

交互式命令行问答，适合调试与快速测试。

### 8.2 Streamlit 模式

```bash
streamlit run frontend/streamlit_app.py --server.port 8501
```

基于 Streamlit 的 Web 界面，快速启动、零前端开发。

### 8.3 FastAPI + SPA 模式

```bash
# 启动后端
uvicorn api.main:app --host 0.0.0.0 --port 8000

# 启动前端（需先 npm install）
cd frontend/spa && npm run dev
```

前后端分离架构，适合生产部署。

## 9. 开发工作流

1. **环境搭建**：安装 Python 依赖（`pip install -r requirements.txt`），启动 Milvus 与 MySQL
2. **配置修改**：编辑 `config.json`，填入数据库地址与 API Key
3. **本地开发**：使用 CLI 模式调试核心逻辑，Streamlit 模式调试界面
4. **接口联调**：启动 FastAPI，通过 Swagger UI（`/docs`）测试接口
5. **测试验证**：上传测试 PDF，验证端到端问答流程
6. **部署上线**：使用 Docker 或 systemd 部署服务

---

## 10. 安全设计

- 用户密码使用 bcrypt 哈希存储，不保存明文
- API 接口采用 JWT Token 认证，Token 有效期可配置
- DeepSeek API Key 仅存于服务端配置文件，不暴露给前端
- 文件上传限制类型为 PDF，限制文件大小（默认 20MB）

## 11. 异常处理

| 异常场景 | 处理策略 |
|---------|---------|
| Milvus 连接失败 | 启动时检测，返回服务不可用 |
| MySQL 连接失败 | 启动时检测，返回服务不可用 |
| PDF 解析失败 | 返回 400 错误，提示文件格式问题 |
| DeepSeek API 超时 | 重试 3 次后返回超时提示 |
| 向量检索无结果 | 返回提示"未找到相关内容"，建议扩大知识库 |
